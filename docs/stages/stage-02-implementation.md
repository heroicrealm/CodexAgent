# Отчёт об этапе 2

Рабочая ветка: STAGE_02. Источник требований: stage02.md и GitHub Issue #4.
По отдельному указанию пользователя результат отправляется в STAGE_04.

Реализованы:

- `src/dispatcher/github/__init__.py`: read-only REST через настроенный gh,
  ограниченные повторы, тайм-аут, Retry-After/reset, полная пагинация,
  проверка repository/author/labels, исключение PR и нормализация.
- `src/dispatcher/github/sync.py`: изоляция ошибок проектов, контракт счётчиков,
  останавливаемый цикл. Неполный ответ не применяется.
- `src/dispatcher/storage/__init__.py`: первая SQLite-миграция (в фактическом
  этапе 1 SQLite отсутствовала), уникальность repository/number, атомарное
  обновление, версии, история, сброс подтверждения, отзыв и восстановление.
- `cli.py`: `poll` и `poll --watch`, обработка SIGINT/SIGTERM в режиме watch.
- Конфигурация и doctor: executables.github, labels.ready,
  security.allowed_authors, default_branch; сохранены старые параметры.
- `tests/test_github.py`: pytest с подменой gh и временной SQLite;
  scripts/test.sh и GitHub Actions запускают весь набор через pytest.
- README и пример YAML: авторизация, два проекта, ручной запуск, модель данных,
  контракт значимых полей и ограничения.

Проверка:

```bash
PATH=/tmp/codex-stage02-venv/bin:$PATH bash scripts/test.sh
```

Результат: 40 passed, 30 subtests passed; compileall успешен.
`git diff --check` успешен.

Тесты проверяют два проекта с разными политиками и отключённый проект,
пагинацию, повторный запуск с повторным открытием SQLite, изменения до/после
подтверждения, метаданные без сброса, отзыв и восстановление, замороженные
снимки активных/терминальных задач, ошибки API и изоляцию проектов,
откат транзакции, безопасные argv/ошибки и остановку watch по SIGTERM.

Ограничения: проверка GitHub выполнялась с mock-ответами, реальный polling
прикладных репозиториев не выполнялся. API обход ограничен 10000 страницами,
ожидание серверных лимитов — 60 секундами на повтор. При более длительном
лимите проход завершится ошибкой без потери очереди. SIGTERM прерывает
ожидание интервала; текущий запрос и ограниченные повторы завершаются.
REST не предоставляет атомарный снимок между страницами; дубли во время обхода
считаются ошибкой и весь результат проекта отбрасывается. До запуска нужна
повторная проверка версии в этапах 3/4. Полноценная служба, одобрение,
исполнение и запись GitHub остаются следующим этапам.
