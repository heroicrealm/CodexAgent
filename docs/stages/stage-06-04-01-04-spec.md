# STAGE 6.4.1.4 — Автоматическая очистка рабочих каталогов
Статус: утверждено (варианты A/A/A). База: STAGE_06_04_01. Реализация только в STAGE_06_04_01_04.

## Назначение
Автоматически освобождать принадлежащие диспетчеру рабочие каталоги Git worktree, вложения, логи и архивы предыдущих итераций после устойчиво зафиксированного перехода Issue в done/cancelled. Сохранять SQLite-историю, метаданные попыток, коммиты, PR и ветки (локальные и origin). Не удалять служебный repository clone. Никаких удалений в review/running/pending/failed/interrupted/revoked/rejected.

## Исходная архитектура
Использовать существующие GitWorkspaceManager и TaskWorkspaceCleanup в src/dispatcher/workspace.py; текущие архивы previous-<attempt_id> (git worktree move), attachments-<attempt_id>, registry .dispatcher-artifacts.jsonl и SQLite. Проверить актуальные имена таблиц, схемы, переходы состояний, scheduler, daemon start/poll, миграции и тесты перед изменениями. Не строить параллельную систему учёта. Путь задачи определяется через project.id + issue number, но ключи SQLite и связи должны быть уникальны по проекту и GitHub issue ID, не только по номеру.

## Функциональный контракт
1. В той же транзакции SQLite, где фиксируется терминальное решение done/cancelled, создавать/обновлять durable cleanup job (idempotent unique task generation). При иных путях смены состояния, включая sync GitHub, обеспечивать тот же результат. Если существующая архитектура не позволяет единую транзакцию, применять гарантированную сверку состояния при каждом цикле и старте.
2. Фоновый цикл daemon обрабатывает очередь без ручного poll; ручной poll может инициировать сверку, но не является необходимым условием. Не блокировать основной цикл, GitHub polling или другие проекты.
3. Перед каждой попыткой в транзакции подтвердить terminal state, неизменность идентичности task/attempt, отсутствие активного Codex и конкурирующей очистки. Не чистить после повторного открытия/перезапуска итерации. Блокировка/lease с безопасным recovery после смерти процесса.
4. Cleanup удаляет зарегистрированные текущий worktree и все предыдущие archived worktrees штатным git worktree remove (без force для грязных деревьев), затем разрешённые attachments/archives/dispatcher files, registry и пустой task dir. Обеспечить идемпотентность при частичной очистке; git worktree metadata проверять, отсутствие уже удалённых объектов считать успехом. Не удалять local/remote branches, repository clone и пользовательские файлы.
5. Учёт архивов всех итераций должен быть durable: previous-* и attachments-* не теряются при очередном retry; сохранять ownership и валидировать метаданные. Поддержать существующие данные, где ownership доступен из истории попыток; не угадывать владение по одному имени каталога. Архивы хранятся до done/cancelled.
6. Для каждого cleanup job: pending/running/completed/failed, attempts, timestamps, next_retry_at, last_error, project/task identity; схему реализовать миграцией в принятом проектом стиле. Не смешивать cleanup state со state Issue. Не допускать дубликатов, включая crash/restart и повторный poll.
7. Политика повторов: первая попытка сразу, затем через 1, 5, 15 минут (всего четыре попытки). После исчерпания — failed без бесконечного автоматического цикла. После рестарта pending и осиротевшие running возобновляются с сохранением attempts/next_retry_at; failed остаётся диагностируемым и допускает явный ручной retry через CLI (встроить в существующий интерфейс без ломания команд).
8. На старте и периодически сверять существующие terminal Issue и каталоги, включая задачи, завершённые до установки миграции. Автоматически ставить cleanup только при подтверждённом владении и безопасной проверке. Небезопасные/неизвестные legacy объекты сохранять и диагностировать, не удалять наугад.
9. Путь обязан находиться в workspace на Linux FS; запрет traversal, symlink escape, symlink races насколько практически возможно. Не использовать shutil.rmtree для невалидированных каталогов; неизвестные файлы, dirty worktree, некорректный manifest/registry, посторонние worktrees и несовпадение Git ownership — остановить удаление с диагностикой. Не трогать чужие рабочие каталоги.
10. Логи структурированные с project, issue, cleanup_id, attempt, result/error; CLI show должен позволять понять состояние очистки. Ошибка cleanup не меняет done/cancelled и не блокирует остальные задачи. Конфиденциальные данные в лог не выводить.

## Тесты и приемка
- done/cancelled: текущий worktree, вложения, служебные файлы, все архивы предыдущих итераций исчезают; Git worktree list чист; repository clone, локальные/удалённые ветки, история SQLite и PR сохраняются.
- review/running/failed/interrupted и активный exec: очистки нет.
- dirty/unknown files, traversal/symlink, corrupt registry/manifest, чужой worktree: данные сохраняются, понятная ошибка.
- crash до/после git worktree remove, между unlink и SQLite commit, во время архивации, после terminal transition: после restart завершить безопасно без двойного удаления.
- повторный poll, конкурентные worker/daemon, повторный start: одна операция на поколение задачи.
- retry intervals 1/5/15 минут с управляемыми часами, исчерпание, ручной retry.
- legacy terminal issues, несколько проектов с одинаковым issue number, несколько previous-* архивов, архивы вложений.
- unit/integration и реальный локальный Git; запустить scripts/test.sh и pytest по принятой схеме; не требовать GitHub сети для unit tests.
- обновить README, документацию миграции и регламент диагностики. Никакого автоматического удаления веток и GitHub объектов.

## Границы
Не менять workflow PR/merge и бизнес-семантику done/cancelled; не создавать новый статус Issue. Сохранять поддержку Ubuntu WSL2, Docker-independent CLI и конфигурируемых проектов. Перед кодированием зафиксировать найденные несовместимости контракта с текущей схемой и предложить минимальное совместимое решение.
