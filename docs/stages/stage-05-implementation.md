# STAGE_05: реализация и проверка

Issue #15: форматирование вынесено в `src/dispatcher/rendering.py`.
`queue` и `show` используют `table` по умолчанию; `--format json` сохраняет
прежний контракт, включая JSON-строки snapshot/observed. Сбор данных остаётся
в CLI; renderer получает ту же модель и не обращается к сети или Store.

Queue использует имена проектов из конфигурации по repository и исходный порядок
Store (`repository, number`). Фильтр ready сохранён. Все состояния по-прежнему
попадают в выборку: название queue не означает только pending. ANSI-палитра
централизована, включается для TTY с непустым TERM кроме dumb и без NO_COLOR.
Заголовки и другие ячейки сокращаются с многоточием; минимальная ширина таблицы
7 колонок. Применены стандартные unicodedata и shutil без новых зависимостей.

Show читает snapshot.body целиком, включая пустую строку, без обрезки Markdown
и абзацев. Отсутствующий/невалидный snapshot или body не вызывает ошибку.
Текстовый вывод обезвреживает управляющие символы терминала, сохраняя LF и TAB.
Поля служебных попыток выводятся по явному списку: origin_url, process_identity,
PID и пути worktree не печатаются. Явный JSON сохраняет прежний полный набор полей.
Пользовательский текст Issue, как и раньше в JSON, может содержать собственные
чувствительные данные; renderer не пытается угадывать или редактировать его смысл.

Проверка фактической схемы: у decisions результат называется `result`,
не `outcome`; текстовый renderer использует `result`. Остальные контракты Store
сохранены. Не менялись status, poll, workflow, схема БД и семантика очереди.
Инициализация таблиц ExecutionStore при show сохранена из прежней реализации.

Автотесты: JSON regression по всем полям и типам задач, заполненные decisions,
command_diagnostics, attempts, quota, result_publication; offline show;
полный Unicode/Markdown body, некорректные snapshots, несколько проектов,
фильтрация, порядок, пустая очередь, длинные заголовки и узкие терминалы;
TTY/non-TTY, TERM, NO_COLOR, отсутствие ANSI оформления в JSON.
Запуск: `bash scripts/test.sh` (pytest и compileall).

Ограничение: ширина Unicode оценивается по combining и East Asian Width.
Сложные emoji ZWJ, флаги и неоднозначная ширина символов зависят от терминала:
точное совпадение ширины таких grapheme clusters не гарантируется.
Ручные проверки используют временную SQLite и конфигурацию, без GitHub/Codex.
