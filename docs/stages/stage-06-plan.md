## Исключено из прежнего плана
- Настройки `auto_create_pr` и override в Issue.
- Сценарий `review` без PR.
- Отдельная команда `pr create` как штатная часть жизненного цикла.
- Непосредственный переход `review → pending` без закрытого unmerged PR.

## Организация
Дочерние ветки `STAGE_06_01` … `STAGE_06_08` от `STAGE_06`; каждый подэтап принимается отдельно, затем сливается в родительскую ветку. Общий PR `STAGE_06 → main` — после приёмки 6.8.

## Минимальные сквозные тесты
1. Успешный Codex → push → PR → review → merge → done → Issue completed.
2. Push успешен, PR не создан: не выставлять review; после рестарта создать/найти PR без Codex.
3. PR закрыт без merge → rejected → новое approve (в том числе без редактирования Issue) → pending → прежняя ветка → push → reopen прежнего PR → review.
4. Rejected → cancelled → Issue not_planned; безопасная локальная/удалённая очистка, без удаления чужой ветки.
5. Многопроектность: два Issue #1 из разных репозиториев не конфликтуют; внутренние связи по GitHub ID.
6. Сетевые сбои, рестарты, повторные события, недоверенные команды, терминальность, отсутствие force push.

### Уточнение реализации 6.4.1.6 (Issue #36)

Терминальное состояние `review_on_error` с меткой `dispatcher:review-on-error`
сохраняется до ручного решения человека; автоматических переходов в done/cancelled
или повторных запусков нет. Доказанный merged канонический PR исключает reopen;
сетевые ошибки и одиночные HTTP-коды остаются retry/reconcile. До удаления owned
worktree обязателен обычный push и подтверждённый remote SHA; сбои сохраняют данные
и возобновляют только публикацию. Диагностический комментарий доставляется через
устойчивый outbox без дубликатов. Исправимые ошибки подготовки — discovered с
отзывом подтверждения. Подробности и границы классификатора:
[отчёт 6.4.1.6](stage-06-04-01-06-implementation.md).
