## 3. Принятые ограничения и отложенные работы

1. **GitHub PATCH body не является атомарным CAS.** Вариант A с повторным GET и независимым read-back сокращает, но не исключает окно гонки с пользовательским редактированием. Пользователь ранее утвердил данное ограничение.
2. При конфликте канонической ветки автоматическое освобождение локального claim и retarget не поддерживаются. При сомнении в принадлежности/ресурсах требуется новая Issue. `reset-claim` может быть отдельным проектом после анализа безопасности.
3. **Единое состояние `blocked` для всех видов Issue** утверждено архитектурно и вынесено в самостоятельный подэтап **6.4.3.8**, не является блокирующим требованием приёмки 6.4.3.3. До него диагностируемые препятствия подготовки могут оставлять Issue в `pending` с комментариями GitHub.
4. Контроль терминальности/merge дочерних задач, интеграционный запуск, PR контейнера, ручные Issue и повторная интеграция относятся к 6.4.3.4–6.4.3.7.
5. Ручная проверка kill -9 во время сетевого запроса, multiple-daemon на разных машинах, permission-denied/timeout, реальные 100+ Sub-issues, повторный poll/restart с детальной трассировкой всех внешних операций и отдельное подтверждение CI не заявлены как пройденные; для них имеется автоматическое покрытие разной степени полноты.

## 4. Условия дальнейшего перехода

6.4.3.4 реализует мониторинг **только непосредственных** детей, доказательство merged-to-parent для done и правило `child_detached_with_open_pr`. До этого `awaiting_children` является корректной точкой остановки контейнера.

**Рекомендация:** принять завершённый функциональный объём 6.4.3.3 с перечисленными ограничениями. Не объявлять реализацию 6.4.3 в целом завершённой и не переносить будущие функции 6.4.3.4–6.4.3.8 в результат 6.4.3.3.
