## Решение

**Этап 4 принят заказчиком и закрыт с оговорёнными ограничениями проверки.** Это решение относится к реализованному объёму STAGE_04; перенос в main выполняется отдельным Pull Request и не означает автоматического merge.

## Реализованный функционал

- Автоматическое резервирование подтверждённых задач, планировщик, учёт параллелизма и состояний.
- Изолированные Git worktree, запуск Codex CLI, проверка результата и push в целевую ветку, переход задачи в review.
- Интеграция чтения квот Codex через App Server, блокировка новых стартов при неизвестной/низкой квоте.
- Распознавание и загрузка GitHub-вложений с ограничениями безопасности и manifest.
- Публикация итогов попытки в GitHub Issue и сохранение данных исполнения.
- Контракт консервативной очистки артефактов после принятия задачи (done).
- Читаемая кириллица в JSON-выводе queue/show/poll/poll --watch при сохранении формата JSON.

## Проверки и подтверждения

- **Ручная интеграционная проверка заказчика — успешно:** диспетчер получил задачу из реального GitHub-репозитория, Codex CLI выполнил её, диспетчер выполнил push и перевёл задачу в review.
- Анализ изменений #12 и #13 — замечания устранены на уровне кода; соответствующие тесты присутствуют в ветке.
- Результаты запуска полного набора тестов в окружении заказчика для окончательного состояния ветки в этой приёмке отдельно не подтверждены.
- **Не проверялись вручную:** скачивание реальных GitHub-вложений и сценарии исчерпания/восстановления квот Codex. Эти ограничения явно приняты заказчиком при закрытии этапа.
