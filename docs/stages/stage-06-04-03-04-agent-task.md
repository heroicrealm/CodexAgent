# Задание Codex-агенту — 6.4.3.4

**Ветка:** `STAGE_06_04_03`. Работать только в `heroicrealm/CodexAgent`.

Изучить [общее ТЗ 6.4.3](stage-06-04-03-spec.md), [ТЗ этапа 6.4.3.4](stage-06-04-03-04-spec.md), реализацию 6.4.3.3 и существующие PR/SQLite/transition компоненты.

## Последовательность реализации

1. Провести краткий архитектурный аудит интеграционных точек, не дублировать `task_pull_requests` и существующие PR ownership / evidence guards.
2. Добавить при необходимости очередную атомарную добавочную SQLite миграцию **после 614**; историческую `VERSION=602` не менять. Хранить поколение интеграции, неизменяемый снимок детей, PR, merge evidence и готовность.
3. Сделать сервис мониторинга непосредственных детей контейнера в `awaiting_children`: полная GitHub-пагинация, устойчивые identities, фильтрация по ready/истории, сохранение исторических связей.
4. Проверять `done` только по **каноническому merged PR в parent branch**. Проверять `cancelled` на незавершённые конфликтующие PR/операции. `state=all` и удаление head branch после merge обязательно покрыть.
5. Реализовать однозначную диагностику `child_detached_with_open_pr` и остальных PR/relationship конфликтов; интегрировать в существующий durable diagnostic outbox без повторных комментариев.
6. При полном подтверждении готовности сохранять `ready_for_integration` и снимок поколения; не переводить контейнер в `running/review` и не выполнять Codex/PR контейнера (6.4.3.5).
7. Обновить CLI show/queue, конфигурацию только при необходимости, документацию и тесты.

## Запреты

Никакой рекурсии Sub-issues, каскадного управления состояниями детей, auto-merge, force push, скрытого retarget, искусственных коммитов или удаления веток. Не реализовывать преждевременно обычные manual Issue, интеграционный Codex и состояние blocked для всех Issue: это следующие подэтапы.

## Проверки и отчёт

Обязательны unit/integration тесты PR identity, merged-to-parent, closed-unmerged, cancelled, detach/open PR, stale/ambiguous GitHub, retry/restart/параллельный poll и регрессия существующих сценариев. Выполнить `source .venv/bin/activate && bash scripts/test.sh`, `git diff --check`, документировать точные результаты и непроверенные внешние сценарии в `docs/stages/stage-06-04-03-04-report.md`.

Не создавать/сливать PR и не оформлять приёмку без отдельного подтверждения пользователя.
