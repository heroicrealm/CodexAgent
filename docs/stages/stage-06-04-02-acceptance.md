## Реализовано

1. Необязательный YAML-блок `dispatcher` с параметрами `branch` и `base_branch`, обратная совместимость с legacy `Target branch:` / `Целевая ветка:`.
2. Создание `codex/issue-N` при отсутствии имени, создание именованной ветки от выбранной базы, использование уже существующей ветки из актуального origin.
3. Полное исключение служебного блока и legacy-строки из prompt Codex; сохранение исходного тела Issue.
4. Запрет прямой работы в защищённой ветке, защита от конфликтов владения и перезаписи Git-истории.
5. Интеграция с SQLite (добавлена миграция 613), повторным выполнением, диагностикой и CLI `show`.
6. Публикация PR в указанную `base_branch`, в том числе в неосновную ветку.

## Наблюдения

В [Issue #60](https://github.com/heroicrealm/CodexAgentPlayground/issues/60) после ошибки `invalid_codex_config` некоторые повторные попытки подтверждения меткой GitHub получили `unverified`. Команда CLI `approve` перевела исправленную задачу в `pending`, далее она штатно выполнилась. На новом Issue повторное подтверждение через GitHub прошло нормально. Причина временного отказа не установлена; воспроизводимого блокирующего дефекта на момент приёмки нет. Наблюдение сохраняется для будущей диагностики, при повторении потребуются `command_diagnostics` и журнал событий.

## Архитектурные решения и отложенные работы

- Сохраняем модель **одна исполняемая Issue — одна рабочая ветка — один PR**. Возможна общая родительская ветка для последовательных Issue; каждая выполняется в собственной ветке.
- Поддержка GitHub Sub-issues рассматривается как будущий этап **6.4.3**, начинается с проектирования.
- Автоматическая очистка опубликованных Git-веток отложена до решения по Sub-issues; сейчас не включена в 6.4.2.
- Очистка локальных worktree остаётся в действующем жизненном цикле.
