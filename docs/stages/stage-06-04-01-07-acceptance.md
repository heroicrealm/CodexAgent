## Реализовано
- Снятие `codex-ready` во время выполнения: durable Detach, блокировка дальнейшей публикации, естественное завершение Codex, безопасная очистка worktree.
- `dispatcher:emergency-stop`: логическая остановка конкретной задачи без принудительного завершения Codex, сохранение метки и диагностики.
- Превышение времени выполнения Codex: диагностический комментарий в GitHub Issue без убийства процесса и без автоматического перевода задачи в ошибку; durable timeout outbox с дедупликацией.
- Обычный `stop` ожидает завершения; только явный административный `stop --force` разрешает сигналы завершения.
- Устранён обязательный cgroup gate; неопределённость состояния процессов препятствует опасной очистке.
- Исправлен обнаруженный на Issue #41/#42 дефект повторного взятия в работу после Detach: оставшаяся локальная Git-ветка архивируется при подтверждённой принадлежности, новая итерация создаётся от актуальной базовой ветки. Добавлена миграция `detach_refs` и регрессионные тесты.

## Ограничения
Полное удержание произвольных дочерних процессов, ушедших через `setsid`/`setpgid`, не гарантируется. При неопределённом состоянии зарегистрированных процессов автоматическая очистка блокируется. Stronger containment не входит в критерии завершения актуальной версии этапа и может быть отдельным развитием.
