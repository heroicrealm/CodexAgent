## Известные ограничения / принятый риск

Для HTTP-снимков GitHub с **одинаковым** `server_observed_at` невозможно строго доказать порядок противоречивых изменений только по этому времени. Более старые наблюдения отклоняются, равные могут приниматься. Legacy-снимки без серверного времени также не входят в аттестованный сценарий replay, хотя не разрешают автоматический Reattach.

Риск документирован в `docs/stages/stage-06-04-01-08-audit.md` и **принят для этапа 6.4.1.8**. Дальнейшее усиление гарантий при равных временных метках требует отдельного архитектурного решения и не блокирует текущую приёмку.
