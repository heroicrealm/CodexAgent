## 2. Автоматическая регрессия
Проверить, что покрыты:
- Одна Issue — одна каноническая branch/PR; повторное исполнение в прежней ветке, reopen того же PR, отсутствие force push.
- `rejected → pending → running → review`, повторное approve, версионирование и stale commands.
- `review_on_error`: сохранность push, диагностика, cleanup и запрет возобновления.
- Detach во всех допустимых состояниях, natural drain running, commit/push, ошибки push, retry без повторного Codex, cleanup и комментарии.
- Reattach: достоверное новое наблюдение, `discovered`, новое approve, прежняя ветка/PR, stale events/outbox, terminal states.
- `codex-config`: defaults, частичные поля, явные значения, безопасный YAML, дубли, invalid refs, Unicode, длинные заголовки, номера >9999, конфликт чужой ветки, configuration_error, идемпотентный комментарий и повторная авторизация.
- SQLite: миграции, legacy PR, многопроектность, restart/crash recovery, идемпотентность.
- CLI `queue`/`show`, логи и init labels.

Добавить только недостающие тесты. Для обнаруженного дефекта сначала воспроизводящий тест, затем минимальное исправление. Запустить `python -m pytest -q` и `git diff --check`; зафиксировать точные результаты. Исходная контрольная точка: 688 passed, 30 subtests passed (6.4.1.8).
