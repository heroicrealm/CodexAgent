# План исправления 6.4.1

**Родительская ветка:** STAGE_06; **рабочая:** STAGE_06_04_01.  
**Основание:** утверждённое [ТЗ 6.4.1](stage-06-04-01-spec.md).

| Шаг | Работы | Результат |
|---|---|---|
| 6.4.1.1 | Аудит кода, SQLite, GitHub API, гонок, документации | Отчёт с картой изменений, рисками, планом миграции и тестами; без изменения runtime |
| 6.4.1.2 | Модель данных, миграции, tracking_generation, legacy | Сохранение истории и единой канонической связи Issue–branch–PR |
| 6.4.1.3 | Повторное выполнение в старой ветке и reopen старого PR | Без новых веток/PR, без force push, устойчивые retries |
| 6.4.1.4 | Терминальное review_on_error | Диагностика, push до очистки, исключение из мониторинга |
| 6.4.1.5 | Detach по снятию codex-ready | Ожидание running, push, комментарий, безопасная очистка |
| 6.4.1.6 | Reattach по повторной метке | Новая generation/discovered, прежние ветка/PR, stale fence |
| 6.4.1.7 | Регрессионные и ручные интеграционные тесты, документация | Проверены все сценарии ТЗ и обратная совместимость |

Каждый шаг оформлять отдельным заданием/приёмкой по согласованию. Не сливать ветку в STAGE_06 до общей приёмки корректировки. После неё обновить общий план этапа 6, особенно противоречащие требования 6.5–6.8.
