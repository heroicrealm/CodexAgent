# STAGE_05 — Рефакторинг CLI: queue и show

## Основание
Сверено с `main`: `src/dispatcher/cli.py`. Существующий интерфейс: `queue`, `show <project> <issue>`; обе команды выводят JSON. `show` получает данные из локальной SQLite и включает decisions, command_diagnostics, attempts, quota, result_publication. `snapshot` и `observed` являются JSON-строками. Unicode в JSON уже поддерживается.

## Цель и границы
По умолчанию человекочитаемый вывод только для `queue` и `show`; `--format json` сохраняет существующий машиночитаемый контракт (имена полей, типы, состав, включая вложенные JSON-строки). Команды `status`, `poll`, `projects` (не реализована), логика scheduler, GitHub, хранения и исполнения вне объёма.

## queue
- Таблица с колонками: ID Issue, проект, заголовок, статус.
- Сохранять текущую фильтрацию по готовым проектам, выборку и порядок.
- Название проекта брать из конфигурации по repository; не хардкодить проекты.
- Цвет статуса при поддержке ANSI/TTY; без ANSI для redirected stdout и JSON. Не полагаться только на цвет; предусмотреть NO_COLOR. Выбор палитры централизовать.
- Длинные заголовки, кириллица, Unicode, пустая очередь, узкий терминал — корректный вывод без аварий; учитывать видимую ширину, не длину байтов.
- `queue --format json` выдаёт JSON-массив в прежнем формате.

## show
- Сохранить синтаксис `show <project> <issue>`.
- Структурированные разделы: идентификатор и репозиторий, заголовок, статус, ветка и прочие доступные метаданные; **полный текст Issue** из локального `snapshot.body`; далее решения, диагностика, попытки, квоты, публикация результата (показывать данные только если присутствуют; не придумывать значения).
- Текст Issue выводить полностью, сохраняя переводы строк, абзацы и Markdown как обычный текст. Не выполнять сетевой запрос при `show`: команда должна работать offline при остановленном диспетчере. При отсутствующем/невалидном snapshot/body показать безопасную отметку об отсутствии, не падать.
- `show --format json` возвращает существующий JSON-объект без изменений схемы; body остаётся внутри snapshot, не менять тип snapshot.
- Исключить случайную печать чувствительных значений и ANSI в JSON.

## Реализация
- Вынести форматирование из бизнес-логики в отдельный общий модуль (или небольшие модули); единая модель данных и два renderer: table/text и JSON.
- Формат по умолчанию `table`, явно `--format table|json` на обеих командах; прежние позиционные аргументы и глобальный `--config` сохранить.
- Не вводить тяжёлую обязательную зависимость без обоснования; проверить работу в Ubuntu/WSL2.
- Ошибки и exit codes сохраняются.
- Обновить README/help с примерами и предупреждением, что по умолчанию формат поменялся.

## Тесты
- JSON-regression: сравнить состав, типы и значения для queue/show с текущим контрактом, включая snapshot/observed и diagnostics.
- Таблица queue: пустая, несколько проектов, длинные и русские заголовки, Unicode, сортировка, фильтрация, ширина терминала, TTY/no-TTY, NO_COLOR, JSON без ANSI.
- Show: полный body с Markdown, кириллицей, многострочным текстом, отсутствующий/невалидный snapshot, журнал решений, attempts, quota, result_publication, offline.
- `bash scripts/test.sh` и ручная проверка CLI.

## Критерии приёмки
Команды queue/show по умолчанию читаемы; JSON доступен через --format json без нарушения контракта; ANSI только в поддерживаемом терминале; show показывает полный текст Issue из локального snapshot; другие команды и workflow не изменены; тесты проходят.
