# Приёмка этапа 2 — Интеграция с GitHub Issues

**Проект:** Codex Task Dispatcher (`heroicrealm/CodexAgent`)  
**Ветка:** `STAGE_02` → `main`  
**Основание:** `docs/stages/stage02.md`, Issues #4 и #6.  
**Решение:** этап принимается по результатам анализа реализации и тестового покрытия; PR подготовить без автоматического merge.

## Проверенные результаты

- Реализованы чтение GitHub Issues через `gh api`, пагинация, исключение PR, проверка repository, меток и allowlist, безопасный вызов без shell.
- Добавлены SQLite-хранилище, идемпотентная синхронизация, история, версии, транзакции, отзыв и восстановление.
- Согласована модель: `discovered` — ожидание подтверждения; `pending` — подтверждено и ожидает запуска; `running → review → done` — последующие этапы; `revoked` — утрата готовности. `approved` исключён из рабочих переходов.
- `Store.confirm()` проверяет ожидаемую версию; значимое изменение подтверждённой задачи сбрасывает подтверждение. Для выполняемых и терминальных задач снимок не перезаписывается.
- Миграция SQLite v2 преобразует прежние `approved` и `pending`, сохраняет версии и историю, не затрагивает активные и терминальные записи.
- Обновлены README, общее ТЗ, спецификация этапа, отчёт реализации и тесты.
- Подтверждено, что `STAGE_02` опережает `main` и не отстаёт от неё; слияние не выполнено.

## Проверка качества

Агент сообщает: **61 passed, 30 subtests passed**, `compileall` и `git diff --check` успешны. Код и тесты проверены чтением файлов GitHub. **Независимый запуск тестов и реальный polling GitHub в рамках данной приёмки не выполнялись**; результаты тестирования указаны по отчёту агента.

## Границы этапа

Не включены команда approve/reject и планировщик очереди (этап 3), исполнение Codex/worktree (этап 4), публикация PR по задачам (этап 5), полноценная фоновая служба (этап 6). `poll` и `poll --watch` доступны отдельно, `start` пока не включает polling.

## Итог

**Этап 2 принят с оговоркой о необходимости подтверждения тестов средствами CI перед merge.** Критических замечаний по результатам статической проверки не выявлено. Рекомендуется объединить `STAGE_02` с `main` после успешных проверок PR. Issues #4 и #6 можно закрыть после завершения приёмки и слияния.
