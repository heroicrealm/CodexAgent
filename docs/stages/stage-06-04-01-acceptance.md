## Сверка с ТЗ §1–§9

- **§1–§2:** одна каноническая ветка и PR на Issue; повторная доработка и повторное открытие прежнего PR без force push и автоматического merge.
- **§3:** terminal `review_on_error`, диагностический комментарий и сохранение опубликованных результатов.
- **§4:** Detach: запрет новых запусков, natural drain текущего Codex, commit/push с подтверждением remote SHA до cleanup, сохранение worktree и durable retry при ошибках, идемпотентный комментарий (D2/D3 исправлены).
- **§5:** Reattach: новое поколение, discovered и новый approve; сохранение канонических branch/PR/SHA, fail closed при неопределённости.
- **§6:** безопасный `codex-config`, ошибки подготовки возвращают в discovered и требуют нового approve; генератор имени ветки и provenance — исключения D1/D4 ниже.
- **§7:** миграции и durable SQLite для истории попыток, публикаций, stop/cleanup и восстановления.
- **§8:** CLI, диагностика, метки и эксплуатационные документы актуализированы.
- **§9:** регрессия и ключевые ручные интеграционные проверки выполнены в указанном ниже объёме.

## Проверки и доказательства

По [отчёту агента 6.4.1.9](stage-06-04-01-09-agent-report.md) полный автоматический прогон на Python 3.14.4: **719 passed, 30 subtests passed, 0 failed, 0 skipped**, `git diff --check` успешен. Это результат, заявленный агентом; независимый повторный запуск в ходе оформления данного акта не выполнялся. Тесты используют локальные Git/SQLite, но stub/mock GitHub API и Codex CLI.

Пользователь подтвердил успешное ручное тестирование:
1. Detach во время running: естественное завершение, GitHub push, комментарий, очистка.
2. Detach из review: PR остаётся открытым, комментарий и cleanup.
3. Reattach: discovered, новое подтверждение, прежняя ветка.
4. Rejected → повторное approve → reopen прежнего PR → done.
5. Ошибка codex-config → исправление → новое approve.
6. Restart: состояние сохранено, повторного исполнения нет.

Редкие искусственные отказы push/reopen, отдельные stale/legacy/remote race, custom init и многопроектность не выдаются за проверенные вручную; их механизм покрыт автоматическими тестами. Подробности: [ручной чек-лист](stage-06-04-01-09-manual-checklist.md). Ссылки на тестовые Issue/PR, SHA и live логи не предоставлены.

## Согласованные исключения — обязательный перенос

**D1.** Генерация/выбор имени ветки: формат `CODEX-NNNN-<нормализованный-заголовок>`, номера >9999, Unicode, ограничения длины, коллизии и безопасный fallback. Текущая реализация использует legacy `codex/issue-N` или заданную ветку. **Не реализовано; включить в следующий этап.**

**D4.** Сохранять независимые признаки `explicit/default` для `base_branch` и `branch_name` и достоверную provenance в SQLite. **Не реализовано полностью; выполнить совместно с D1 в следующем этапе.**

**L1.** Снимки GitHub с равным серверным timestamp не всегда позволяют доказать порядок противоречивых событий. Ограничение принято ранее; более старые timestamps отбрасываются, неоднозначность не является доказательством нового поколения.

D1/D4 не считаются закрытыми этим актом; при планировании следующего этапа необходимо перенести требования и тестовые сценарии §6.2–§6.3 без потери деталей.
