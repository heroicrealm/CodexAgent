## Проверенный результат
- Python 3.12+ пакет, установленная команда `codex-dispatcher`, Ubuntu/WSL2.
- YAML-конфигурация нескольких проектов без зашитых имён целевых репозиториев; валидация и пример.
- Runtime-каталоги, блокировка одного экземпляра, PID/start-time проверка, структурированные JSONL-логи.
- Команды `start`, `status`, `stop`, `stop --force`. Обычный stop ожидает, force сначала посылает SIGTERM группам процессов, затем после настраиваемого grace timeout (по умолчанию 5 с) — SIGKILL оставшимся.
- `doctor`: проверки версий git/gh/codex, `gh auth status`, SSH Agent и ключей с учётом определённого транспорта Git, доступности каталогов и конфигурации.
- Автоматические тесты и GitHub Actions.

## Допустимые ограничения
- На этапе 1 не реализуются polling Issues, исполнение реальных заданий Codex, worktree, публикация PR/отчётов.
- Linux-специфичные `/proc`, `flock`, `pidfd`, `waitid`; отсутствие ротации журналов.
- Гарантии остановки распространяются на управляемые группы процессов, а не на произвольно демонизированные процессы, покинувшие группу.
- SSH Agent не заменяет авторизацию GitHub API через `gh`; парольная фраза SSH-ключа не сохраняется.
