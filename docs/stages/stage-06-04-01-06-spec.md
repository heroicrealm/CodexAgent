# ТЗ 6.4.1.6 — Терминальное состояние review_on_error

**Основание:** [ТЗ 6.4.1](stage-06-04-01-spec.md), §3 и §6.4; [актуальный план](stage-06-04-01-plan.md).
**Ветка реализации:** `STAGE_06_04_01_06`; **целевая ветка PR:** `STAGE_06_04_01`.

## Цель
При ошибке, для которой явно предусмотрен `review_on_error`, прекратить соответствующую подготовку/операцию и зафиксировать терминальное решение, не теряя результатов Codex и не возобновляя его автоматически.

## Функциональные требования
1. Ввести/поддержать публичное терминальное состояние `review_on_error` с точной GitHub-меткой `dispatcher:review-on-error`; учесть конфигурацию меток, `init`, `doctor`, `queue`, `show`, сохранение в SQLite, переходы, аудит и тесты.
2. Классифицировать ошибки по явным условиям. Основной нормативный случай — доказанная неустранимая невозможность повторно открыть канонический PR после повторной доработки. Не считать временные сетевые ошибки, неопределённый результат запроса или одиночный HTTP-код без проверки фактического состояния доказательством неустранимости. Не создавать второй PR.
3. После выявления такой ошибки остановить новые попытки подготовки/запуска Codex. Сохранить причину и намерение терминального решения устойчиво к рестарту, с защитой от конкурирующих poll/scheduler/monitor.
4. Если результаты выполнения ещё не опубликованы, выполнить commit/push обычным способом, проверить удалённый SHA и принадлежность ветки. При сбое/неопределённости push сохранять worktree и повторять только публикацию/сверку; Codex повторно не запускать. Состояние терминального решения не освобождает от обязательства сохранности.
5. Однократно публиковать комментарий Issue через устойчивый outbox с причиной, веткой, commit SHA, каноническим PR, состоянием публикации и указанием на ручное решение. Повторы polling, рестарт и неопределённый результат отправки не должны создавать дубликаты.
6. После подтверждения сохранности результатов безопасно удалить только принадлежащие задаче worktree и временные загруженные файлы, используя уже реализованный механизм очистки 6.4.1.4. Не удалять чужие ресурсы, удалённую ветку, PR, аудит и историю попыток.
7. Исключить терминальную задачу из новых запусков Codex, автоматического PR-monitoring и автоматического изменения состояния. Повторные `approve`, `codex-ready`, `poll` и перезапуск демона не должны оживлять её.
8. Человек вручную решает дальнейшую судьбу задачи в GitHub; диспетчер не делает auto-merge и не переводит `review_on_error` в `done`/`cancelled` автоматически.
9. Сохранить прежние сценарии: ошибки YAML, отсутствие `base_branch`, конфликт чужой ветки и другие исправимые ошибки параметров до запуска Codex — `pending → discovered` с отзывом подтверждения и диагностикой согласно §6.4 общего ТЗ, **не** `review_on_error`.

## Инварианты и восстановление
- Одна Issue — одна каноническая ветка и один канонический PR; никакого force push.
- Транзакционное сохранение намерения/состояния, fencing версии/generation, идемпотентный outbox; повтор после сбоя не запускает Codex и не дублирует комментарии.
- При невозможности безопасной публикации или очистки сохранять данные и диагностировать проблему, а не объявлять успешную очистку.
- Не менять существующие терминальные состояния `done` и `cancelled`.

## Критерии приёмки
1. Невозможность reopen PR → фиксация ошибки → подтверждённый push → `review_on_error`, метка, один комментарий, cleanup, отсутствие повторного запуска.
2. Временная ошибка GitHub → retry/reconcile, без преждевременного `review_on_error`.
3. Ошибка push → сохранение worktree; повтор только публикации; без потери результатов и без повторного Codex.
4. Рестарт в каждой критической фазе, повторный poll, неопределённый результат GitHub, гонки: нет дублированных PR/комментариев/попыток.
5. Повторный approve и codex-ready не активируют терминальную задачу.
6. Исправимые ошибки параметров возвращают в discovered; ранее принятые сценарии rejected→pending, cleanup, merge→done, cancelled и многопроектность не регрессируют.
7. Автотесты и ручной сценарий в тестовом репозитории; README/config/docs отражают новое состояние и метку.

**Ограничение:** код не изменяется до выполнения задания агентом; данное ТЗ не разрешает расширять перечень терминальных ошибок произвольно.
