# Ручной чек-лист 6.4.1.9 — НЕ ВЫПОЛНЕН

Репозиторий: `heroicrealm/CodexAgentPlayground`. Исполнитель: пользователь
после независимого аудита. Агент не создавал Issue/PR, не выполнял merge,
не менял метки/права/remote и не запускал live Codex.
Все M1–M9 требуют live GitHub/Codex, если внутри явно не указан локальный
или stub-подсценарий. Отсутствие безопасной подготовки означает «не проверено».

Перед началом записать commit dispatcher, Python/Codex/gh/git версии, путь отдельной
конфигурации и backup БД, project id, task label, разрешённого автора и base branch.
Использовать отдельный workspace, не рабочие файлы пользователя. Для диагностики:

```sh
codex-dispatcher queue
codex-dispatcher queue --format json
codex-dispatcher show PROJECT ISSUE
codex-dispatcher show PROJECT ISSUE --format json
codex-dispatcher poll
```

Approve выполняет только уполномоченный человек после проверки версии:
`codex-dispatcher approve PROJECT ISSUE` либо новая GitHub approve-команда.
Не применять force/reset, не удалять worktree/БД вручную. Ошибки публикации сначала
диагностировать, сохранив локальный SHA и audit; `cleanup-retry PROJECT ISSUE`
применим только к неуспешному cleanup после проверки сохранности результатов.
Не выполнять merge/закрытие Issue вне явно проводимого пользователем M1/terminal
решения. Чувствительные токены и содержимое credentials в артефакты не включать.

Общие поля прогона:
- Исполнитель / UTC: **не заполнено**.
- Commit / версии / config / backup: **не заполнено**.
- Issue и PR URLs, global IDs, branch, SHA до/после: **не заполнено**.
- Итог: **не проверено**.

## M1. Полный цикл Issue → PR → rejected → approve → reopen → done

Шаги: Создать небольшую Issue с проверяемым изменением и ready-меткой. Выполнить poll, записать version/issue_id. Подтвердить актуальную версию разрешённым человеком. Дождаться review, записать branch, PR ID/URL и SHA. Закрыть PR без merge. Дождаться rejected. Спустя отдельную серверную секунду дать одно новое approve. Дождаться push/reopen, сверить ID/branch и ancestry. Только пользователь вручную выполняет merge. Дождаться done.

Ожидаемый результат: Одна каноническая branch/PR; новая attempt, обычный push, тот же PR открыт повторно. После ручного merge Issue completed; комментарий содержит actor/time. Poll/restart не дублирует PR/комментарий.

Фактический результат: **не выполнено**.

Артефакт: **не заполнено** — ссылка Issue/PR, UTC, снимок show, SHA, лог/ответ API; указать live/local/stub.

## M2. review_on_error

Шаги: На отдельной тестовой Issue получить rejected. В согласованной тестовой среде обеспечить доказанную неустранимую причину reopen (например, удаление head репозитория допустимо только для отдельного одноразового fork; не удалять общий Playground). Если безопасно воспроизвести нельзя, отметить «не проверено». Сохранить фактический API-ответ/диагностику. После нового approve дождаться обработки. Проверить remote SHA до cleanup. Повторить poll/restart и relabel ready.

Ожидаемый результат: Новый PR не создаётся. Временные 404/422/timeout сами по себе не достаточны для terminal. При доказанной причине — review_on_error, review-on-error label, один комментарий с branch/SHA/PR/причиной и публикацией. Cleanup только после push. Ни approve, ни ready не оживляют terminal. Дальнейшее решение вручную.

Фактический результат: **не выполнено**.

Артефакт: **не заполнено** — ссылка Issue/PR, UTC, снимок show, SHA, лог/ответ API; указать live/local/stub.

Проверить, что Codex заканчивает естественно, затем проверить локальный и remote SHA, cleanup, stop_requests и комментарий. Повторить poll.

Ожидаемый результат: По общему ТЗ: нет нового Codex и принудительного сигнала; доступные результаты commit/push до cleanup; один комментарий с UTC/actor/branch/SHA. ## M4. Push error/retry/restart без повторного Codex

Выполнить задачу; записать attempt, число запусков Codex и неопубликованный SHA. Перезапустить dispatcher, проверить worktree. Восстановить доступ, дождаться retry. Отдельно повторить с detach running, учитывая D2.

Ожидаемый результат: Ошибка сохраняет commit/worktree. Retry/restart не вызывает Codex повторно и не создаёт новый PR. Cleanup лишь после подтверждённого remote SHA. Отдельно записать обычную, review_on_error и detach публикацию; успех первой не доказывает detach.

## M5. Reattach и stale events/outbox

Шаги: После M3 дождаться завершения cleanup. Сохранить generation, branch/PR ID/SHA и старое approve. Вернуть ready в более позднюю серверную секунду, выполнить poll/show. До нового approve проверить отсутствие запуска. Выдать новое approve, проверить branch/PR/SHA. В отдельной локальной копии БД/адаптере воспроизвести доставку старых событий/outbox (не редактировать рабочую БД). Проверить relabel для done/cancelled/review_on_error.

Ожидаемый результат: Новая generation/discovered без подтверждения; старые команды/outbox без эффектов. Требование прежней опубликованной branch/PR имеет пробел D2: ожидается fail closed с диагностикой, а не слепой новый запуск. Terminal не оживает. Равные server timestamps L1 записывать отдельно, не использовать как доказательство порядка.
