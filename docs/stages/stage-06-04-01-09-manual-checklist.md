Перед началом записать commit dispatcher, Python/Codex/gh/git версии, путь отдельной


Не выполнять merge/закрытие Issue вне явно проводимого пользователем M1/terminal
решения. Чувствительные токены и содержимое credentials в артефакты не включать.

## M1. Полный цикл Issue → PR → rejected → approve → reopen → done

Шаги: Создать небольшую Issue с проверяемым изменением и ready-меткой. Выполнить poll, записать version/issue_id. Подтвердить актуальную версию разрешённым человеком. Дождаться review, записать branch, PR ID/URL и SHA. Закрыть PR без merge. Дождаться rejected. Спустя отдельную серверную секунду дать одно новое approve. Дождаться push/reopen, сверить ID/branch и ancestry. Только пользователь вручную выполняет merge. Дождаться done.

Ожидаемый результат: Одна каноническая branch/PR; новая attempt, обычный push, тот же PR открыт повторно. После ручного merge Issue completed; комментарий содержит actor/time. Poll/restart не дублирует PR/комментарий.

Фактический результат: **не выполнено**.

Артефакт: **не заполнено** — ссылка Issue/PR, UTC, снимок show, SHA, лог/ответ API; указать live/local/stub.

## M2. review_on_error

Если безопасно воспроизвести нельзя, отметить «не проверено». Сохранить фактический API-ответ/диагностику. После нового approve дождаться обработки. Проверить remote SHA до cleanup.
