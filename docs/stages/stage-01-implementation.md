ТЗ `docs/stages/stage-01.md` и полное описание Issue #2 прочитаны перед изменениями.
Рабочая ветка: `STAGE_01`; main не изменяется, PR не создаётся, Issues не закрываются.

Существующая инфраструктура этапа сохранена: конфигурация нескольких проектов,

Polling, реальные задания, worktree и публикация результатов не реализуются.

Исправления Issue #2:

- Doctor запускает `git --version`, `gh --version`, настроенный Codex с `--version`.
  Каждая команда имеет таймаут 15 секунд; OSError, TimeoutExpired и ненулевой код
  дают FAIL. `gh auth status` остаётся отдельной проверкой API-аутентификации.
- SSH Agent: проверяются SSH_AUTH_SOCK и `ssh-add -l`, включая отсутствие ключей,
  недоступный агент и таймаут. При известных SSH remote проблема даёт FAIL,
  при неизвестном транспорте — WARN. Отсутствие агента для HTTPS не даёт FAIL.
  Вывод команд, ключи, переменные окружения и тексты исключений не логируются;
  парольная фраза не запрашивается. Протокол определяется по remote существующих
  клонов включённых проектов в workspace/id. Ограничения URL rewrite и SSH config
  описаны в README; owner/name и API-авторизация транспорт не определяют.
- Добавлен положительный целочисленный `dispatcher.force_grace_timeout_seconds`
  с default 5. SIGTERM получает вся группа; SIGKILL применяется после grace только
  к ещё активным группам. Ожидание и лимит параллелизма учитывают потомков после
  завершения непосредственного ребёнка. Zombie не считаются активными.
- Непосредственный ребёнок освобождается только после завершения группы: его PID
  остаётся зарезервированным, поэтому PGID не переиспользуется во время отмены.
  Завершённые группы удаляются из учёта, повторная отмена безопасна. Внешний wait/poll
  лидера обнаруживается и приводит к ошибке до сигналов. Методы Lifecycle исполняет
  один scheduler. Изменение принадлежности process group/setsid не поддерживается;
  такие процессы намеренно не разыскиваются по потенциально переиспользованным PID.
  Для произвольной демонизации потребуется cgroup. Непрерываемый kernel sleep может
  задержать завершение после SIGKILL; состояние не очищается до завершения группы.
