# V2.3.C — доработка итогового OUTPUT: ссылка на commit и корректные ссылки на файлы

**Основание:** интеграционный тест Issue #2, PR #3 в `heroicrealm/CodexAgentPlayground`; подтверждённый полный цикл до `done`.

## Обнаруженное поведение

`Publisher.phase_output()` добавляет в OUTPUT итоговое сообщение Codex из `workspace/results/<execution_id>.txt` как сырой Markdown. Codex может вернуть ссылку вида `[readme.md](/home/.../workspace-v2/worktrees/PROJECT/e-.../readme.md)`. В GitHub она превращается в неработающий адрес `https://github.com/home/...`. Отчёт также не даёт отдельной ссылки на коммит, полученный после push.

Конкретный сценарий: `heroicrealm/CodexAgentPlayground`, Issue #2, PR #3, result head commit `94f9eaa4316109cf25b3d980ac5c002408723703`, merge commit `6c1d7280bcc8a955bcdc5f25cea003fce8d4cdb2`. **Не захардкодить эти значения.**

**Уточнение по времени формирования отчёта:** OUTPUT с `Result commit` впервые публикуется после подтверждённого push и создания/обнаружения PR, то есть **до merge**. При последующем merge тот же OUTPUT обновляется до состояния `done`, но `Result commit` остаётся ссылкой на опубликованный результат Codex; SHA merge-коммита не заменяет его и не требуется для данной доработки. Не нужно ждать merge для появления ссылки на результат.

## Требуемые изменения

1. В OUTPUT добавить поле `Result commit:` — кликабельная ссылка `https://github.com/{owner}/{repo}/commit/{sha}` на **последний успешно опубликованный result_commit текущего execution**, только когда push подтверждён и SHA валиден. Использовать данные SQLite (`executions.result_commit`, `issues.repository`), не добавлять GitHub GET к обычному poll. Не подменять result commit SHA коммитом слияния PR; merge commit при желании показывать отдельным именем лишь при наличии достоверных данных, но это не часть задачи.
2. При наличии PR оставлять нынешнюю ссылку на него. В итоговом отчёте ясно различать `Result commit`, `PR` и состояние.
3. Перед публикацией финального текста Codex преобразовать Markdown-ссылки на локальные файлы worktree. Если путь указывает **внутрь именно worktree данного execution**, включая проверку `resolve()`, и соответствующий относительный файл существует **в дереве подтверждённого result_commit**, преобразовать ссылку в `https://github.com/{owner}/{repo}/blob/{sha}/{escaped-relative-path}`. Для точного URL корректно кодировать компоненты пути (включая пробелы, Unicode, #, ?, %). Работать с Git в уже доступном checkout/worktree без скачивания ресурсов, когда это возможно.
4. Если файл не подтверждён или путь не принадлежит текущему worktree — **убрать только Markdown-ссылку**, оставив читаемую подпись (`readme.md`); не публиковать абсолютный путь пользователя, не придумывать GitHub URL. Для абсолютных локальных путей, встречающихся вне Markdown-ссылки, также предусмотреть минимальную обработку, чтобы не разглашать домашние каталоги в OUTPUT, сохранив полезный текст.
5. Не менять содержимое сохранённого оригинального stdout Codex в `workspace/results/`: преобразовывать только **представление для публичного OUTPUT**. Не выполнять произвольные shell-команды, полученные из текста агента; экранировать Markdown URL. Не изменять ссылки http(s), относительные ссылки репозитория и обычный текст без необходимости.
6. OUTPUT строить из уже сохранённых данных, повторное формирование после `review → done` не должно приводить к повторному запуску Codex, повторному PR или необоснованному обновлению комментария.
7. Для отсутствующего `result_commit`, неподтверждённого push и ручных задач `run_codex: false` вывод должен быть корректным без ложных ссылок и исключений.
8. Не изменять каноническую модель состояний, число таблиц SQLite или их схему, не добавлять новых фоновых GitHub-запросов.

## Тесты

- URL на подтверждённый result commit имеет верный repository и SHA, в PR-случае не заменяется merge commit.
- Нет ссылки на commit без подтверждённого push.
- Абсолютная ссылка внутри worktree на существующий committed файл заменяется ссылкой на `blob/<sha>/path`.
- Неизвестные, чужие, symlink escape и отсутствующие в commit файлы остаются читабельным названием без локального пути.
- Пробелы, Unicode и специальные символы в имени файла.
- Внешние https URL и текст без путей не портятся.
- Повторное обновление OUTPUT и переход `review → done` идемпотентны.
- Все тесты V2.3.A/B проходят.

## Границы

Реализовать в `V2_3_IMPLEMENTATION` как доработку V2.3.C; не создавать PR до общей приёмки. Сведения о результате интеграционного сценария и тестов добавить в отчёт C (или создать локальный отчёт, если документа ещё нет). Предыдущая отдельная заявка V2.3.C на подробную диагностику ошибок и раздельное хранение оригинала в SQLite / очищенной версии на GitHub остаётся в силе и не должна подменяться этой доработкой.
