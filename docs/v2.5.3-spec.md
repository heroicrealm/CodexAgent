# V2.5.3 — Ubuntu Native Service: окончательное техническое задание

**Проект:** Codex Dispatcher V2  
**Репозиторий:** `heroicrealm/CodexAgent`  
**Базовая ветка:** `CODEXAGENT_V2`  
**Рабочая ветка:** `V2_5_3_UBUNTU_SERVICE`  
**Базовая версия для аудита:** `2.5.2.post2`  
**Дата:** 2026-11-18  
**Статус:** утверждённая постановка для реализации; приёмка ещё не выполнена.

## 1. Цель и границы

Обеспечить непрерывную работу диспетчера на Ubuntu Server без открытого терминала и активной SSH-сессии, включая автозапуск после перезагрузки. Службой управляет `systemd --user`, пользовательский manager запускается без входа через `loginctl enable-linger`.

Не менять бизнес-логику Issue/PR, scheduler, протокол SQLite, Recovery, Git HTTPS, модель состояний, алгоритм Codex executor и поддержку WSL2/Docker. Не вводить tmux, screen, второго daemon/supervisor или автоматическое обновление.

**Утверждено:** user service + linger; `Restart=on-failure`; обновление только с ручным перезапуском после остановки.

| Компонент | Текущее состояние | Требование |

## 3. Функциональный контракт systemd

Unit: `~/.config/systemd/user/codex-dispatcher.service`. Использовать `Type=exec` на поддерживаемых systemd, `ExecStart` со **стабильным абсолютным** путём `~/.local/bin/codex-dispatcher run` (раскрыть home в момент установки), `Restart=on-failure`, `RestartSec=10s`, `TimeoutStopSec=infinity`, `KillMode=mixed`, `WantedBy=default.target`, `StandardOutput=journal`, `StandardError=journal`, ограничение частых сбоев `StartLimitIntervalSec=300`/`StartLimitBurst=5`.

`WorkingDirectory`, `HOME` и `PATH` должны быть доступны без shell startup scripts. Не включать в unit секреты, логины и токены. Не использовать `User=` внутри user unit, не требовать системного `/etc/codex-dispatcher` и `/var/lib/codex-dispatcher`.

`KillMode=mixed` — целевое решение, которое требуется проверить с настоящим деревом Codex: при штатном stop нельзя посылать SIGTERM дочерним задачам одновременно с главным процессом. Должна быть обеспечена очистка оставшихся процессов после выхода main.

Службу включают отдельно (enable), запускают отдельно (start). `loginctl enable-linger USER` — разовое **явное действие администратора**, без выполнения sudo из установщика. Удаление unit не отключает linger.

## 4. CLI управления службой

Добавить группу `codex-dispatcher service`:

- `install` — проверка user manager, установленной CLI, валидной конфигурации, namespace unit; безопасная атомарная запись unit; `systemctl --user daemon-reload`, `enable`, **без auto-start**. Повторный install с тем же содержимым идемпотентен. Не перезаписывать чужой/вручную изменённый unit; обеспечить проверяемое владение (маркер плюс ожидаемая структура/хеш).
- `start`, `stop`, `restart` — делегировать `systemctl --user`, не обходить systemd и не писать собственный PID-supervisor. `restart` запускает новый процесс только после окончания graceful остановки.
- `status` — systemd active state, enabled, linger, MainPID при наличии, абсолютные пути CLI/unit/config и версия; по возможности дополнить локальным runtime status. Должна быть пригодна при остановленной/неисправной SQLite.
- `logs` — `journalctl --user -u codex-dispatcher`, последние записи и follow.
- `uninstall` — остановить, disable, удалить **только свой** unit, daemon-reload; сохранить пакет, SQLite, UUID, workspace, конфигурацию, credentials и логи.

Ошибки взаимодействия с `systemctl --user` и недоступный D-Bus/user manager выдавать ясно и с ненулевым exit code. Не выполнять команды через shell-интерполяцию пользовательских данных; валидировать пути, владельца, симлинки и права. Существующий `codex-dispatcher stop` — управляющий socket runtime, **не аналог** `service stop`; документация должна рекомендовать именно `systemctl --user stop` для службы.

Команды `service` должны разбирать аргументы до обычного runtime/DB admission, чтобы `service status/logs/uninstall` не зависели от исправности SQLite. `service install` обязан отдельно валидировать необходимые параметры и существование файлов.

## 5. Инициализация, сигналы, аварии

При start использовать прежние проверки config/schema/identity, SQLite, InstanceLock и Recovery. Не создавать отсутствующую БД автоматически. Отсутствие сети при **проверке релиза** не блокирует старт: warning, bounded timeout, без `input()` и чтения stdin.

При штатной остановке: SIGTERM главному процессу → запрет новых запусков → ожидание активного Codex и публикации без фиксированного предела → завершение задач/очистки → закрытие socket, locks, соединений → код 0; `Restart=on-failure` не перезапускает процесс.

При аварийном ненулевом exit systemd пытается перезапустить в пределах start-limit. Не ослаблять Recovery admission: если повторное выполнение задачи запрещено, автоматически его не начинать. Конфигурационные/авторизационные ошибки должны быть диагностируемы; бесконечный restart-loop недопустим. При необходимости скорректировать классификацию кодов выхода или unit `RestartPreventExitStatus`, сохраняя корректную диагностику.

Нельзя считать `KillMode=mixed` достаточным без проверки реального дерева дочерних процессов и системных сигналов.

## 6. Окружение и безопасность

Поддержать существующий XDG resolver: `--config` приоритетен, иначе `$XDG_CONFIG_HOME/codex-dispatcher/config.yaml` или `~/.config/codex-dispatcher/config.yaml`; `dispatcher.root_path` и относительные database/workspace/checkout остаются прежними.

Пользователь службы должен совпадать с владельцем данных, `gh` и `codex` credentials. Действующий Git-транспорт — HTTPS с GitHub CLI credential helper. Установка сервиса не выполняет логин в `gh`/Codex, не переносит credentials, не требует ssh-agent. Предусмотреть отсутствие TTY и возможные ошибки доступа `HOME`/`PATH`/`XDG`. Не включать токены в лог, unit, argv и репозиторий.

## 7. Обновление и удаление пакета

Штатный сценарий: `service stop` → доказать полную остановку → `codex-dispatcher-install` → проверить версию → **ручной** `service start` (или restart при подходящем установленном состоянии). Инсталлятор не должен рестартовать автоматически и не должен обходить shutdown locks. В unit использовать стабильный CLI-линк, не путь поколения venv.

Согласовать `codex-dispatcher-uninstall` с зарегистрированным/включенным unit: не допускать исчезновения исполняемого файла у оставленного enabled unit; выдавать инструкцию о предварительном `service uninstall` либо безопасно делать подтверждённую процедуру. Существующие пользовательские данные не удалять.

## 8. Автоматические тесты (WSL2 + GitHub CI)

Без требований к действующему systemd, внешней сети и реальным credentials:

1. Генерация unit, экранирование абсолютных путей, правильные параметры `ExecStart`, `TimeoutStopSec=infinity`, `KillMode=mixed`, `Restart=on-failure`, start-limit.
2. Отсутствие системного `User=` и неявных `/etc`/`/var/lib` путей.
3. Idempotent install, owner-check, отказ чужому unit/symlink, безопасный uninstall без удаления данных.
4. Mock/stub `systemctl --user`/`journalctl --user`; статусы, ошибки, отсутствие manager.
5. `service status/logs/uninstall` при отсутствующей/повреждённой SQLite.
6. Отсутствие prompt и успешный допуск к runtime после сбоя **только release-check** без TTY.
7. Реальный subprocess без PTY с fake Codex, graceful SIGTERM, завершением future и контролируемым деревом процессов.
8. Регрессии InstanceLock, Recovery, release installer, XDG, WSL2.
9. Сборка wheel, `pytest -q`, compileall, shell syntax checks и CI.

Эти проверки **не считаются подтверждением** работы настоящего Codex под user-systemd.

## 9. Ручная приёмка: Ubuntu Server (S01–S19)

| Код | Проверка | Критерий |
|---|---|---|
| S01 | Установка unit | Unit создан и валиден |
| S02 | Повторный install | Идемпотентно |
| S03 | Запуск | Active, корректный MainPID |
| S04 | Закрытие SSH | Служба продолжает работу |
| S05 | Reboot | Автозапуск при linger |
| S06 | GitHub недоступен при release-check | Нет prompt, запуск не заблокирован release-check |
| S07 | Реальная Issue | Публикация PR |
| S08 | Stop на активной Issue | Graceful без прерывания Codex |
| S09 | Повторный SIGTERM | Не эскалирует до force |
| S10 | Авария main process | Restart в рамках политики |
| S11 | Ошибка SQLite/Recovery | Безопасный отказ |
| S12 | Конкурирующий foreground run | Отказ по locks |
| S13 | Обновление версии | Остановка → обновление → ручной старт |
| S14 | Service uninstall | Пользовательские данные сохранены |
| S15 | Нет авторизации | Диагностика без интерактивного зависания |
| S16 | Журналы | Видны в journalctl |
| S17 | Постоянная ошибка запуска | Start-limit без бесконечного цикла |
| S18 | Stop с живыми потомками | Дочерний Codex не убит преждевременно |
| **S19** | **Настоящий Codex без TTY и tmux** | **После закрытия SSH и после reboot новая Issue выполняется через `codex exec` с публикацией PR, без TTY, prompt и зависших процессов** |

Для S19 проверить отсутствие управляющего терминала у процесса, факт исполнения настоящего Codex CLI (не fake/stub), состояние дочерних процессов и корректность PR. При проблемах сначала исследовать stdin/stdout/stderr, окружение, Codex-авторизацию и особенности версии CLI; **не вводить tmux без отдельного обоснования**.

WSL2 с включённым systemd может использоваться для предварительных интеграционных проверок, но **не заменяет Ubuntu Server acceptance**. S04/S05/S19 обязательны на Ubuntu. Автотесты CI не должны использовать реальные GitHub issue/PR.
