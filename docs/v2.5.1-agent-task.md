# Задание агенту Codex — реализация V2.5.1

**Ветка:** `V2_5_1_INFRASTRUCTURE` (от `CODEXAGENT_V2`).  
**Нормативное ТЗ:** [v2.5.1-spec.md](v2.5.1-spec.md).  
**Контекст будущих поставок:** [v2.5-spec.md](v2.5-spec.md).

## Порядок работы

1. Прочитать обе спецификации, но выполнять **только** ограниченный объём V2.5.1. Проверить актуальный код V2; не использовать V1 как источник контрактов.
2. Составить аудит: `run`, обработка сигналов, InstanceLock/Recovery, config resolver, git clone/fetch/push и авторизация. Кратко описать обнаруженные дефекты и минимальный план исправления.
3. Реализовать исправления только там, где выявлено несоответствие ТЗ. Сохранить graceful stop без таймаута, force stop, PID/UUID и блокировки.
4. Обеспечить HTTPS-only для **служебных** Git remote и операций. Не переписывать существующие SSH remote автоматически; реализовать безопасный явный сценарий перехода или документированную штатную процедуру в границах V2.5.1.
5. Добавить автоматические тесты на выбор HTTPS, отказ от SSH fallback, безопасность credential helper, сигналы и регрессии путей/SQLite.
6. Запустить существующие тесты и форматные проверки репозитория. Подготовить отчёт: изменённые файлы, результаты тестов, известные ограничения, сценарий ручной приёмки.

## Строгие ограничения

Не добавлять Dockerfile, Compose, systemd unit, sudo-обёртку, инсталляторы, публикацию Docker Hub или новую схему SQLite. Не менять XDG resolver, логику Issues/PR/Recovery без доказанной необходимости. Не вводить автоматическую авторизацию, токены в git URL или создание SSH-ключей.

**Не создавать PR и не сливать ветку до отдельного подтверждения ручной приёмки.**
