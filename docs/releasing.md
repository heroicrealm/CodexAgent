# Публикация WSL-релиза

Стабильный Release и тег создаются только после ручной приемки и отдельного разрешения владельца. Workflow `WSL distribution artifacts` собирает проверочный bundle при push/PR или ручном запуске; прав записи и автоматической публикации у него нет. Существующий CI сохраняется.

1. Проверить чистую ветку, CI и отчет ручной приемки. Согласовать конкретный commit. Синхронизировать `pyproject.toml`, `config/config.example.yaml`, release notes и ожидаемую версию в `scripts/smoke-wheel.py` (для этого этапа `2.5.2`). Схему менять только при несовместимости.
2. Выполнить `python3 scripts/embed-wsl.py --check`, pytest, `python3 -m build --wheel`, установить wheel в чистый venv, запустить `--help` и `scripts/smoke-wheel.py` вне checkout. Workflow выполняет эти проверки и сохраняет `wsl-release-candidate`.
3. Для предварительной проверки использовать bundle Actions либо отдельно разрешенный draft/check release. Установщик намеренно игнорирует drafts/prereleases: выбор конкретного проверочного артефакта требует тестового стенда с подменой ответов API, а не публикации стабильного релиза до приемки. Для локальной проверки wheel достаточно установить его в отдельный venv; это не заменяет окончательную проверку доставки после публикации.
4. После отдельного разрешения создать тег `v2.5.2` на согласованном commit. Создать draft Release этого тега, загрузить из одного bundle: единственный `codex_dispatcher_v2-2.5.2-py3-none-any.whl`, `install-wsl.sh`, `uninstall-wsl.sh`, `config.example.yaml`, `SHA256SUMS`, `v2.5.2.md`. Сверить `sha256sum -c SHA256SUMS`, версию wheel и шаблона. Вставить notes из `v2.5.2.md`.
5. Проверить assets и их GitHub SHA-256 digest, затем опубликовать стабильный Release (не prerelease). Проверить `/repos/heroicrealm/CodexAgent/releases/latest`, чистую установку и повторный запуск установщика. Не смешивать артефакты разных сборок. PyPI и git clone для установки приложения не требуются.

Издатель отвечает за доверенные release assets: SHA256SUMS доставляется через HTTPS из того же конкретного релиза; при наличии GitHub asset digest установщик сверяет и сам manifest. Это контроль целостности, не отдельная криптографическая подпись издателя. Зависимости Python устанавливаются pip из настроенного индекса; сам диспетчер — только из wheel релиза.

При изменениях протокола поставки загрузить свежий `install-wsl.sh` из нужного релиза. Исходник встроенного установщика — `scripts/wsl_distribution.py`; после правок выполнить `python3 scripts/embed-wsl.py`, закоммитить оба скрипта. При несовместимости старого установщика документировать это в release notes. Код проверки версий и механизм установки пригодны для Ubuntu native; Windows-службы и systemd не добавляются.
