# Codex Dispatcher в Ubuntu / WSL2

Нужны WSL2 с Ubuntu, Python ≥3.11 с pip/venv, git, GitHub CLI (`gh`), Codex CLI (`codex`), доступ к GitHub и индексу зависимостей Python. Работайте обычным пользователем, без sudo для установщика. В Ubuntu установите системные пакеты `python3`, `python3-pip`, `python3-venv`, `git`, `curl`; `gh` и Codex CLI установите по официальным инструкциям их поставщиков. На Ubuntu с Python <3.11 сначала установите поддерживаемый Python.

Самостоятельно настройте авторизацию:

```sh
gh auth login
gh auth setup-git
codex login
gh auth status
codex login status
```

Установщик проверяет команды и сообщает об отсутствии авторизации, но не меняет credentials. Используйте Linux-каталоги внутри WSL для workspace.

## Получение и установка

После публикации первого стабильного релиза:

```sh
mkdir -p ~/Downloads/codex-dispatcher
cd ~/Downloads/codex-dispatcher
gh release download --repo heroicrealm/CodexAgent --pattern install-wsl.sh --pattern uninstall-wsl.sh --pattern SHA256SUMS
sha256sum --check --ignore-missing SHA256SUMS
sh install-wsl.sh
```

`gh release download` без тега выбирает последний стабильный релиз. Для воспроизводимого получения конкретной версии добавьте `v2.5.2` после `download`. При обновлении формата поставки скачайте новый установщик в пустой каталог. Не используйте скрипт из ветки main. Сам установщик запрашивает последний стабильный Release, показывает версии и требует подтверждение в терминале. Без авторизованного gh публичные артефакты можно скачать браузером со страницы конкретного Release.

Пакет устанавливается обычным wheel в отдельный venv внутри `~/codex-dispatcher`, а `~/codex-dispatcher/.venv` указывает на активную генерацию. Предыдущие генерации сохраняются до удаления программы. Повторный запуск той же версии не заменяет пакет; downgrade запрещен. Сбой загрузки, checksum или pip сохраняет прежний пакет. Чужую `.venv` или чужую короткую команду установщик не заменяет: разберите конфликт вручную, не удаляя рабочие данные.

Команда доступна через `~/.local/bin/codex-dispatcher` без активации venv. Если каталога нет в PATH, добавьте в `~/.profile`:

```sh
export PATH="$HOME/.local/bin:$PATH"
```

Откройте новый терминал. Проверьте:

```sh
codex-dispatcher --help
codex-dispatcher --config-schema-version
~/codex-dispatcher/.venv/bin/python -m pip show codex-dispatcher-v2
```

## Конфигурация и первый запуск

Основной файл — `~/.config/codex-dispatcher/config.yaml`, либо `$XDG_CONFIG_HOME/codex-dispatcher/config.yaml`, если XDG_CONFIG_HOME — абсолютный путь. Параметр `--config /absolute/path` идет **до** подкоманды. Установщик обслуживает стандартный/XDG-файл; перед обновлением при нестандартном `--config` остановите все экземпляры и согласуйте его YAML вручную. Общая блокировка установленного пакета также запрещает обновление/удаление при активном runtime с нестандартным `--config`; установщик не редактирует такие YAML автоматически.

В шаблоне сохранены все настройки. `dispatcher.root_path` вложен в `dispatcher`, содержит абсолютный путь пользователя; литерал `~` не поддерживается. Пути workspace/database разрешаются относительно root. Добавьте тестовый проект в `projects`, например:

```yaml
dispatcher_version: "2.5.2"
config_schema_version: 1
dispatcher:
  root_path: /home/alice/codex-dispatcher
projects:
  - id: sandbox
    repository: alice/dispatcher-sandbox
    base_branch: main
```

Для новой БД используйте явный bootstrap; существующие БД не инициализируйте заново:

```sh
codex-dispatcher db bootstrap
codex-dispatcher init-labels
codex-dispatcher run --once
codex-dispatcher run
```

`run` работает в foreground. Из другого терминала:

```sh
codex-dispatcher status
codex-dispatcher queue
codex-dispatcher stop
```

Штатная остановка ждет выполняющуюся работу; `stop --force` — принудительная остановка. Также поддерживается Ctrl+C в foreground. Пример другого файла: `codex-dispatcher --config /home/alice/test.yaml run --once`. Для подробных CLI/DB/recovery-команд смотрите README и `--help`.

Перед каждым `run`, включая `--once`, выполняется ограниченная тайм-аутом проверка основного API и последнего стабильного релиза. Новая версия дает уведомление и ссылку. Недоступный основной API вызывает `Start dispatcher anyway? [y/N]:`: y продолжает прежний запуск; n, Enter, Ctrl+C завершают запуск. Без терминала — отказ. Если недоступен только Releases, выводится предупреждение и запуск продолжается. Во время выполнения новых сетевых проверок/ограничений не добавлено. `queue`/`status` эту сеть не используют.

## Обновление и схема

Остановите runtime и дождитесь завершения, затем повторно выполните `sh install-wsl.sh`. Установщик проверяет штатные locks/control socket и удерживает runtime-блокировки во время переключения. При активном или неопределенном состоянии отказывает; PID сам по себе не является доказательством остановки.

При схеме 1 обновляется только `dispatcher_version`; проекты, пути и комментарии сохраняются. Для отсутствующей/неверной/новой схемы основной файл сохраняется, создается `config.new.yaml`. Существующий новый файл заменяется только после отдельного вопроса. Сравните оба файла, вручную перенесите свои настройки в новый шаблон, сохраните резервную копию старого, затем замените основной файл. Проверьте `dispatcher.root_path`, проекты, labels и схему. Старые конфиги автоматически совместимыми не считаются. Изменяющие команды блокируются до согласования; `--help`, остановка и диагностическое чтение доступны. При поврежденной структуре основного YAML установщик может отказать, поскольку не может доказать остановку runtime: сначала восстановите корректные пути вручную.

Версия пакета берется из metadata venv, а `dispatcher_version` — только метка YAML. После смены схемы они могут различаться. Повторная установка той же версии не выполняет миграцию: завершите ручное согласование уже созданного файла.

## Диагностика и удаление

При отказе проверьте PATH, Python, `gh auth status`, `codex login status`, доступ к API, путь XDG и `--config`, `config_schema_version`, `db check`, `status`. Не стирайте lock-файлы у работающего runtime. При ошибке установки успех не выводится; старая генерация и пользовательские данные сохраняются. Поврежденный YAML или неоднозначная принадлежность файлов требуют ручного разбора.

После штатной остановки:

```sh
sh uninstall-wsl.sh
```

Удаляются только помеченные установщиком venv и его ссылка CLI. Конфигурация, SQLite, workspace/worktrees, репозитории и credentials сохраняются; весь `~/codex-dispatcher` не удаляется. Для запуска скриптов требуется Python и доступ к зависимостям bootstrap. Публикация описана в [регламенте](releasing.md).
