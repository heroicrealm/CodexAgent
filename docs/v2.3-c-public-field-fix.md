# V2.3.C — исправление ложного сокрытия имени Git-ветки в OUTPUT

**Контекст:** после реализации `docs/v2.3-c-error-diagnostics.md` реальный GitHub-тест Issue #13 в `heroicrealm/CodexAgentPlayground` создал корректную ветку `codex/task-0013`, однако OUTPUT показал `Group branch: [withheld]`. Аналогично Issue #12 в `error`. Ошибка подтверждена чтением кода.

## Первопричина

В `src/dispatcher/error_diagnostics.py`, `public_field()` есть неограниченный поиск `sk-` по всей строке. Имя `codex/task-0013` содержит `sk-` в окончании слова `task-`, поэтому ошибочно распознаётся как секрет. В `Publisher.phase_output()` это имя пропускается через `public_field(branch)`.

## Исправление

1. Устранить ложное совпадение `sk-` внутри обычного слова, сохранив защиту настоящих секретов. Отдельно учитывать синтаксически допустимые Git-ветки и структурированные секреты; проверять конкретные форматы/границы токенов без слепого поиска короткой подстроки. **Не** заменять проверку на безусловный пропуск любого валидного имени ветки: секретоподобная ветка должна оставаться скрытой.
2. `public_field('codex/task-0013') == 'codex/task-0013'`; аналогично `manual/task-0013`, `codex/task-0001`, `codex/task-10000` и существующие пользовательские имена, не являющиеся секретами.
3. Поддельные значения, содержащие образцы GitHub/OpenAI токенов, Authorization/password/secret или локальные пути и управляющие символы, должны и дальше скрываться. В частности, сохранить поведение тестов для `sk-synthetic` и `ghp_SYNTHETIC_DIAGNOSTIC_SECRET`; по возможности добавить примеры реалистичных форматных токенов и токенов внутри составной строки.
4. Убедиться, что `public_field` применяется только к структурированным полям с соответствующей валидацией; необработанные traceback, stderr, исходные тексты исключений **никогда** не публикуются на GitHub. В SQLite полный оригинал сохраняется без маскировки.
5. Добавить регрессионный интеграционный тест формирования `Publisher.phase_output()`: из уже утверждённой Issue #13 после push/PR в `review` вывести `Group branch: \`codex/task-0013\``, затем переход `done` сохраняет имя без `[withheld]`. Аналогично сценарий `error` (Issue #12 / `codex/task-0012`).
6. Проверить отсутствие регрессий безопасного ERROR, ссылок на результат Codex, ручных и пользовательских веток, повторной публикации OUTPUT, изменения схемы SQLite, лишних обращений GitHub.
