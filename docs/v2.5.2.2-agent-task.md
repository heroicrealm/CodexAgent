# Задание агенту Codex — V2.5.2.2 Standalone

**Репозиторий:** `heroicrealm/CodexAgent`  
**Ветка:** `V2_5_2_2_STANDALONE_IMPROVEMENTS`  
**Основное ТЗ:** [v2.5.2.2-standalone-spec.md](v2.5.2.2-standalone-spec.md)

## Обязательное начало

Работай только в указанной ветке (основание: `V2_5_2_1_WSL_DISTRIBUTION`). Прочитай полное ТЗ, затем проверь текущие `pyproject.toml`, `src/dispatcher/__main__.py`, `scripts/standalone_distribution.py`, `scripts/embed-standalone.py`, `install-standalone.sh`, `uninstall-standalone.sh`, документацию, release workflow и тесты. Строго сохраняй механизм ownership и runtime locks. Все ранее выполненные ручные испытания 2.5.2.post1 принимаются как регрессионная база, но новая функциональность требует отдельной проверки.

## Реализация

### A. Версионирование
- Установи дистрибутиву `codex-dispatcher-v2` версию `2.5.2.post2`; обнови YAML-шаблон и связанные тестовые константы. `config_schema_version=1`.
- Подготовь release notes и workflow bundle, но не выпускай Release самовольно.

### B. Проверка актуальности установщика
- Добавь синхронную проверку SHA-256 фактического исполняемого установщика против `install-standalone.sh` последнего стабильного Release **до изменений состояния**.
- Используй существующий проверенный manifest `SHA256SUMS` и digest; если метаданные/контрольная сумма не подтверждаются, откажи без изменений.
- При mismatch: сообщение с URL конкретного релиза, инструкция ручного скачивания/проверки, ненулевой код; никакого самоперезапуска и перезаписи.
- Учти запуск через symlink, начальную установку, запуск уже актуальной версии и все ранние return-ветки.
- Обнови встроенные shell-скрипты из общего источника через генератор; проверь `embed-standalone.py --check`.

### C. Постоянная команда установки
- Добавь `~/.local/bin/codex-dispatcher-install`, указывающую на управляемую установщиком исполняемую копию `install-standalone.sh` (предпочтительно в активном `venv` поколении).
- Скачивай, проверяй checksum и доставляй `install-standalone.sh` совместно с wheel, шаблоном и удалителем.
- Обеспечь корректное переключение поколений, rollback и запрет перезаписи чужих CLI-файлов.
- При удалении убирай только собственную команду и экземпляры установщика. Не удаляй SQLite/config/worktree/credentials.

### D. `--version`
- Добавь глобальную `codex-dispatcher --version` с выводом `Codex Dispatcher 2.5.2.post2`, версия исключительно из `importlib.metadata.version("codex-dispatcher-v2")`.
- Работает без конфигурации, БД, сети и запуска runtime. Не ломай `--config-schema-version`, справку и подкоманды.

### E. Безопасное удаление
- Существующие проверки stopped/ownership оставь.
- До удаления потребуй `Proceed with uninstall? [y/N]:`.
- Только явное y выполняет операцию; n/Enter/EOF/Ctrl+C/non-TTY не удаляют; при non-TTY возвращай ненулевой код; при запущенном daemon отказ до вопроса.
- Не добавляй флаг обхода подтверждения.

### F. Документация/CI
- Актуализируй README, `docs/standalone.md`, `docs/releasing.md`, release notes 2.5.2.post2, workflow и smoke scripts.
- В документации отдельно поясни, что с V2.5.2.post1 пользователь **один раз** скачивает новую версию установщика вручную, после чего использует `codex-dispatcher-install`.
- Не меняй scheduler, GitHub adapters, поведение Issue/PR, Service и Docker.

## Обязательные автоматические проверки

Покрыть тестами: checksum match/mismatch, manifest/digest failure, раннее сравнение при равной версии, symlink на собственный файл, отсутствие неожиданных side effects; доставку и rollback installer CLI; контроль версий; подтверждение и отмену удаления включая отсутствие TTY; повторную установку; regression config/SQLite/queue/runtime locks. Запустить полный pytest, wheel build, isolated pip install, smoke-install, sh -n и `embed-standalone.py --check`.

Используй mock GitHub API и временные HOME/XDG, не реальный аккаунт/секреты.
