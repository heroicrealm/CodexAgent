# V2.5.1: HTTPS Git и ручная приёмка

Диспетчер создаёт служебные clone по `https://github.com/OWNER/REPO.git`.
Значение `gh git_protocol=ssh` не используется. Перед fetch/push/ls-remote
проверяются общий Git directory checkout/worktree, identity проекта, единственный
fetch URL и единственный push URL origin. SSH, credentials в URL, другой repository,
несколько URL и URL rewrite (`insteadOf`/`pushInsteadOf`) дают отказ до сети.
HTTPS redirects и рекурсивные удалённые операции submodule отключены. SSH fallback нет.

## Авторизация

От имени того же пользователя, с теми же HOME и PATH, вручную выполните:

```bash
gh auth login
gh auth setup-git
```

Авторизация Codex также выполняется пользователем через его CLI. Диспетчер не
выполняет login, не читает auth-файлы и не сохраняет токены. Для служебной операции
Git цепочка credential helpers сбрасывается временными `-c` параметрами и используется
`gh auth git-credential` для github.com. Настройки на диске не изменяются; обычный
`credential-store` не получает credentials. `stdin` закрыт, terminal/askpass prompts
отключены. Отсутствующий helper/credentials приводит к ошибке, без SSH fallback.
Успех API или `ls-remote` подтверждает доступ на чтение, но не право push.

Не добавляйте токены в URL, аргументы или конфигурацию remote. Не публикуйте вывод
credential helper и auth-файлы. Удалите URL rewrites из применимого пользовательского,
системного или локального Git config самостоятельно, проверив их назначение.

## Явный перевод существующего служебного SSH checkout

Остановите диспетчер штатным `stop` и дождитесь завершения процесса и его детей.
Не запускайте другие Git-команды во время процедуры. Проверьте `db check`, UUID
установки и принадлежность checkout диспетчеру. Сохраните резервную копию установки
существующим `db backup`; SQLite и workspace не пересоздаются.

Ниже отдельная явная процедура для **стандартного служебного**
`workspace/repos/PROJECT_ID`. Она намеренно отказывается менять checkout в другом
месте, symlink и checkout, общий для нескольких проектов. Перед запуском оператор
проверяет, что каталог создан диспетчером, а не передан из личного рабочего дерева.
Для нестандартного `project.checkout` сначала отдельно подтвердите происхождение и
владение каталогом; этот ограниченный сценарий его автоматически не изменяет.

Выполните из установленного Python-окружения диспетчера, заменив config и project ID:

```bash
python - /absolute/config.yaml PROJECT_ID <<'PY'
import sys
from pathlib import Path
from dispatcher.config import load_config
from dispatcher.db_guard import check
from dispatcher.git import Git, https_url
from dispatcher.locking import InstanceLock

config = load_config(Path(sys.argv[1]))
project = next(p for p in config.projects if p.id == sys.argv[2])
expected_path = config.workspace.absolute() / 'repos' / project.id
configured = (project.checkout or expected_path).absolute()
if configured != expected_path or any(p.is_symlink() for p in (configured, *configured.parents)):
    raise SystemExit('Only the standard, non-symlink managed checkout is supported')
if sum((p.checkout or config.workspace / 'repos' / p.id).resolve() == configured.resolve()
       for p in config.projects) != 1:
    raise SystemExit('Ambiguous checkout ownership')
with InstanceLock(config):
    check(config)
    git = Git(config)
    path = git.checkout(project, create=False)
    if ((path / '.git').is_symlink() or not (path / '.git').is_dir()
            or git.run(path, 'rev-parse', '--show-toplevel') != str(path)):
        raise SystemExit('Expected a standalone managed main checkout')
    git.check_rewrites(path)
    repo = project.repository.casefold()
    allowed = {f'https://github.com/{repo}.git', f'git@github.com:{repo}.git',
               f'ssh://git@github.com/{repo}.git'}
    for opts in ((), ('--push',)):
        urls = git.run(path, 'remote', 'get-url', *opts, '--all', 'origin').splitlines()
        if len(urls) != 1 or urls[0].casefold() not in allowed:
            raise SystemExit('Fetch/push repository identity is unproven; no changes made')
    config_file = path / '.git' / 'config'
    if config_file.is_symlink():
        raise SystemExit('Symlink Git config refused')
    before = config_file.read_bytes()
    backup = config_file.with_name('config.pre-https')
    with backup.open('xb') as stream:
        import os
        os.fchmod(stream.fileno(), 0o600)
        stream.write(before)
    try:
        url = https_url(project.repository)
        git.run(path, 'config', '--local', '--replace-all', 'remote.origin.url', url)
        git.run(path, 'config', '--local', '--replace-all', 'remote.origin.pushurl', url)
        git.verify_remote(path)
    except BaseException:
        config_file.write_bytes(before)
        raise
print('HTTPS origin verified; branches, commits and worktrees preserved')
PY
```

Скрипт не делает fetch/push и не меняет worktree, ветки, коммиты, UUID или SQLite.
При конфликте identity ничего не изменяется. Копия `.git/config.pre-https` не
перезаписывается; перед повторным запуском оператор проверяет и архивирует её.
После успеха проверьте `git worktree list --porcelain`, ветки и HEAD по сохранённым
значениям, затем сделайте неинтерактивный read-only HTTPS `ls-remote` с тем же
окружением. В тестовом проекте проверьте штатную публикацию результата. Проверка
push с реальными credentials остаётся ручной приёмкой.

## Ручная приёмка этапа

1. В тестовой установке сохраните UUID, пути SQLite/workspace, ветки и worktrees.
   Выполните `db check`; проверьте `status`, `queue`, `show` при остановленном runtime.
2. Запустите foreground `run --once`, затем обычный `run`. При активной долгой задаче
   пошлите SIGTERM, повторите SIGTERM и убедитесь, что задача и публикация завершаются,
   новые задачи не допускаются, процесс выходит без лимита ожидания. Повторите SIGINT.
3. Отдельно проверьте `stop --force`: завершаются только группы управляемого ребёнка;
   сторонний процесс продолжает работу. Второй экземпляр с общей SQLite или workspace
   должен получить отказ. После остановки handlers/lock/socket освобождены.
4. Без `ssh-agent`, с `gh git_protocol=ssh`, проверьте новый HTTPS clone, fetch и
   публикацию в тестовый GitHub repository. Удалите HTTPS credentials в отдельном
   тестовом HOME: операция должна отказать без пароля и без токенов в публичном выводе.
5. Задайте старый SSH origin, затем отдельный чужой push URL: оба случая должны
   отказать без изменения remote и сетевого SSH. Верните доказанный origin и примените
   явную процедуру выше; сравните ветки, коммиты, worktrees и UUID/SQLite.

Systemd, Docker и установщики проверяются в следующих этапах. PR и слияние ветки
выполняются только после отдельной ручной приёмки.
