## 1. Цель и область

Закончить механизм поставки Standalone: глобальный `codex-dispatcher --version`, постоянно доступная `codex-dispatcher-install`, защита установщика при несовпадении SHA-256 с последним стабильным релизом, интерактивное подтверждение удаления. Не выполнять самозамену и самозапуск нового установщика; не изменять схему SQLite, обработку Issue/PR, Service или Docker.

Основание: `docs/v2.5.2.2-standalone-spec.md`, `docs/v2.5.2.2-agent-task.md`, `docs/v2.5.2.2-implementation-report.md`.

## 4. Замечания и ограничения

1. В одном промежуточном локальном прогоне тестовый Python harness после визуально введенной `y` получил `confirm=False` и завершился кодом 0 без установки. В прямом тесте ввод `y` имел Unicode `0x79`; при повторном запуске диагностического harness `confirm=True`, установка прошла. Причина разового расхождения **не установлена**. Как косметическое улучшение предлагается явно печатать `Installation cancelled.` при отказе от установки; отсутствие этого сообщения не блокирует выпуск.
2. До публикации post2 проверка SHA установленного post2 installer ожидаемо выдавала mismatch с Latest post1; после публикации post2 повторный запуск подтвердил совпадение SHA и актуальность пакета.
3. Проверка SHA манифеста с GitHub asset digest сохраняет существующую модель доверия к GitHub Release; отдельная подпись издателя не реализуется и не требовалась.
4. В версии post2 при изменении установщика будущего релиза требуется вручную скачать новые байты скрипта; автоматическое самообновление намеренно не предусмотрено.
5. Приведение release workflow к ручному запуску выполнено непосредственно перед подготовкой PR: по новой голове ветки необходима обычная проверка GitHub Checks; приемка функциональности проводилась на том же коде установщика и wheel.
