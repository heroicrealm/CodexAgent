# V2.5.2.1 — отчет реализации и приемка

Ветка: `V2_5_2_1_WSL_DISTRIBUTION`, основана на `V2_5_2_WSL_DISTRIBUTION`.
Пакет и dispatcher_version: `2.5.2.post1`, схема: `1`.

## Изменения

Установщик получает wheel, YAML и uninstall-standalone.sh из одного ответа GitHub Release и сверяет каждый SHA-256 с SHA256SUMS. Проверка GitHub digest самого manifest сохранена. Удалитель устанавливается с правами 0755 внутрь нового собственного поколения venv. `~/.local/bin/codex-dispatcher-uninstall` указывает на `~/codex-dispatcher/.venv/uninstall-standalone.sh`.

Атомарная смена `.venv` переключает пакет и удалитель одновременно. При исключении восстанавливаются прежние `.venv`, ownership-маркер и YAML; созданные при неуспешной транзакции ссылки удаляются. Предыдущий скрипт не переписывается. Чужая команда удаления, включая dangling symlink, вызывает отказ. Повтор той же версии восстанавливает отсутствующую команду; отсутствующий или неисполнимый скрипт требует новой проверенной установки.

Удалитель удаляет обе собственные команды, `.venv`, все поколения со скриптами и ownership-маркер. Конфигурация, SQLite, workspace, checkout и credentials сохраняются. Базовый каталог и `.standalone-install.lock` остаются: удаление lock inode нарушило бы взаимное исключение параллельных процессов. Проверки остановки, global/runtime locks, ownership и пересечения пользовательских путей с venv сохранены.

Исходники обработки Issue, scheduler, PR и формата конфигурации не изменены. Обновлены руководство, release notes, workflow упаковки, тесты и smoke-проверки. Тег, Release и PR не создавались; push не выполнялся.

## Воспроизведение до публикации

Из корня checkout в отдельном Python venv с build, pytest и зависимостями проекта:

```sh
python -m pytest -q
python scripts/embed-standalone.py --check
(cd dist/2.5.2.post1 && sha256sum -c SHA256SUMS)
python -m pip download --dest /tmp/post1-wheelhouse dist/2.5.2.post1/*.whl
python scripts/smoke-install.py dist/2.5.2.post1/codex_dispatcher_v2-2.5.2.post1-py3-none-any.whl /tmp/post1-wheelhouse
```

Для реального обновления подготовьте отдельный checkout исходной ветки и wheel:

```sh
mkdir -p /tmp/post1-legacy-source
git archive V2_5_2_WSL_DISTRIBUTION | tar -x -C /tmp/post1-legacy-source
python -m build --wheel --outdir /tmp/post1-legacy-source/dist /tmp/post1-legacy-source
python scripts/smoke-install.py dist/2.5.2.post1/codex_dispatcher_v2-2.5.2.post1-py3-none-any.whl /tmp/post1-wheelhouse /tmp/post1-legacy-source
```

Smoke использует временный HOME, не затрагивает рабочую установку и удаляет стенд после проверки. В legacy-каталоге должен быть единственный wheel 2.5.2.

## Ручная приемка доставки

Публикация требует отдельного разрешения. До нее `/releases/latest` не обязан содержать этот кандидат: используйте локальные проверки выше. После разрешенной публикации проведите следующие шаги на отдельном пользователе/стенде WSL2 и Ubuntu native:

1. Скачать в пустой каталог `install-standalone.sh` и SHA256SUMS из `v2.5.2.post1`, выполнить `sha256sum --check --ignore-missing SHA256SUMS`, затем `sh install-standalone.sh`. Повторить отдельно на чистом HOME и на установке 2.5.2. При обновлении обязательно использовать новый установщик.
2. Проверить `~/.local/bin/codex-dispatcher --help`, `--config-schema-version` (1), `~/codex-dispatcher/.venv/bin/python -m pip show codex-dispatcher-v2` (2.5.2.post1), `dispatcher_version` (2.5.2.post1). Убедиться, что прочие поля YAML и комментарии прежние.
3. Проверить `readlink ~/.local/bin/codex-dispatcher-uninstall`, `readlink ~/codex-dispatcher/.venv`, права 0755 и совпадение SHA-256 установленного скрипта с bundle.
4. Сохранить контрольные суммы YAML, остановленной SQLite, файлов workspace и credentials. Для новой БД сначала выполнить `codex-dispatcher db bootstrap`. Использовать только тестовую конфигурацию/проекты.
5. Запустить `codex-dispatcher run` в одном терминале. Во втором вызвать `codex-dispatcher-uninstall`: ожидается ненулевой код возврата, сообщение об активном диспетчере и сохранность программы. Повторить для runtime с нестандартным `--config`.
6. Выполнить `codex-dispatcher stop`, дождаться завершения foreground процесса. Запустить `codex-dispatcher-uninstall`: ожидается успех, исчезновение обеих команд, `.venv`, поколений со скриптами и ownership-маркера. Сравнить контрольные суммы пользовательских файлов. Lock-файлы и каталоги с данными должны остаться.
7. На отдельном тестовом HOME создать чужую команду удаления (обычный файл или ссылку): установка должна отказать и сохранить ее. Снова установить на чистом HOME и повторно запустить установщик той же версии: лишнее поколение не создается.
