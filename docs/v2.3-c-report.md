# V2.3.C — доработка публичного OUTPUT

Дата: 2026-11-07. Ветка: `V2_3_IMPLEMENTATION`.
Основание: `docs/v2.3-c-output-improvements.md`.

## Изменения

- `execution.py`: OUTPUT содержит отдельную кликабельную ссылку `Result commit`
  из SQLite только при подтверждённом push и полном валидном SHA. PR также
  представлен явной ссылкой; состояние показано отдельно.
- `services.py`: наблюдение PR больше не перезаписывает уже подтверждённый
  результат публикации. Последующий успешный push обновляет его штатным путём;
  неудачная повторная публикация сохраняет предыдущий подтверждённый SHA.
- `output.py`: публичное представление локальных Markdown-ссылок проверяет
  принадлежность именно worktree текущего execution, включая `resolve()`.
  Подтверждённые файлы получают blob-ссылки с URL-кодированием пути, остальные
  ссылки заменяются подписью. Поддержаны angle destinations, пробелы, Unicode,
  специальные символы, скобки и суффиксы `:line:column`. Внешние URL и
  относительные ссылки сохраняются. Для голых путей в типичных локальных
  каталогах (`/home`, `/Users`, `/root`, `/tmp`, `/var`, `/workspace`, `/mnt`)
  остаётся имя файла. Это минимальная обработка путей, не универсальный фильтр
  секретов или произвольного текста.
- `git.py`: наличие обычного файла проверяется через локальный `git ls-tree`
  строго в дереве сохранённого коммита, с literal pathspec. Каталоги и symlink
  не считаются подтверждёнными файлами. После удаления worktree используется
  существующий checkout; клонирования, fetch и GitHub GET для проверки нет.
- `tests/test_output.py`: восемь регрессионных проверок, включая параметризацию.

Оригинальный stdout в `workspace/results` не изменяется. Схема SQLite,
канонические состояния, фоновые GitHub-запросы и V1 не менялись. Формирование
OUTPUT не запускает Codex и не создаёт PR; подтверждённое неизменное тело
не публикуется повторно. Ручное исполнение корректно показывает подтверждённый
коммит опубликованной ветки без вызова Codex.

сохранение SHA при изменении головы PR и merge, повторный успешный и неуспешный
push, committed/untracked/missing/deleted файлы, чужие пути, symlink escape,
специальные имена, сохранность stdout, ручное исполнение, отсутствие лишней
публикации при повторном OUTPUT и переходе review → done, локальная проверка
после удаления worktree. Git выполняется в изолированных временных репозиториях;
GitHub и Codex в тестах подменены.

## Автоматические имена веток по issue_number

Доработка по `docs/v2.3-c-branch-naming.md`, 2026-11-07.
В `StateService.approve()` новые группы без явного `dispatcher.branch` получают
`codex/task-{issue_number:04d}` либо `manual/task-{issue_number:04d}`.
Ширина минимальная: #10 → `task-0010`, #10000 → `task-10000`.
Глобальный `issue_id` остаётся ключом SQLite, execution и связей групп;
схема и миграции не менялись. Других мест генерации этих имён в V2 нет.

Явные имена сохраняются буквально. Уже утверждённые группы, включая группы
со старым форматом имени, не переименовываются при повторном утверждении
или открытии БД. Корректирующие Issue наследуют закреплённую ветку группы.
Проверки конфликтов в Git, жизненный цикл и обращения к GitHub не менялись.

Добавлены 15 регрессионных случаев:

- Номера 1, 10, 125, 9999, 10000 для Codex и ручного исполнения при отличающемся
  глобальном ID; проверяется сохранение глобального ключа и отсутствие GitHub-вызовов.
- Два репозитория с #10 и разными глобальными ID сохраняют независимые группы
  с одинаковым допустимым именем ветки.
- Явное пользовательское имя и закреплённое имя старого формата сохраняются
  при повторном открытии БД, повторном утверждении и добавлении коррекции.
- Для обоих префиксов существующая удалённая ветка автоматически вычисленного
  имени блокирует исполнение до запуска Codex, не создаёт PR и сохраняет
  исходный SHA, в том числе после отмены и очистки.

Прежние ожидания автоматически сформированных имён в тестах обновлены.
Полный штатный набор V2: `.venv/bin/python -m pytest -q` — **132 passed**
(117 прежних и 15 новых случаев), 8.30 с.
`.venv/bin/python -m compileall -q src tests` и `git diff --check` успешны.
В первом прогоне два новых теста конфликта выявили неверный ключ тестового
FakeAPI (ID вместо номера); фикстура исправлена, повторный полный прогон успешен.

Git-проверки используют локальные временные bare-репозитории; GitHub и Codex
подменены. Реальные ветки не переименовывались, внешние запросы и реальный
запуск Codex не выполнялись. V1 в этой доработке не менялся и повторно
не запускался. Подробная диагностика ошибок остаётся отдельной задачей.
Работа выполнена в `V2_3_IMPLEMENTATION`, PR не создавался.
