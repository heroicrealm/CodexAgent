# V2.5.1 — аудит и отчёт реализации

Ветка: `V2_5_1_INFRASTRUCTURE`. Проверен актуальный код V2; V1 не использовался
как источник контрактов. Объём ограничен V2.5.1. Ручная приёмка ещё не выполнена.

## Аудит перед исправлениями

| Область | Реальные точки входа и вывод | Минимальное исправление |
| --- | --- | --- |
| Foreground | `__main__.main` → `Runtime.run`, в текущем процессе; `--once` уже существует | Сохранить единственный runtime |
| Сигналы | `runtime.py`: SIGINT/SIGTERM вызывали `stop()` с обычным Lock; сигнал внутри admission мог повторно захватить его и зависнуть. Обработчики устанавливались после startup/recovery | Обработчик только отмечает graceful stop, без lock/force; установка до startup и восстановление в finally |
| Завершение worker | Цикл мог выйти при `stopping` и уже завершённом future, не вызвав `future.result()` | Всегда дочитывать результат future, включая ошибку |
| Force и дети | `execution.ProcessRunner`: отдельная session/group, supervisor с унаследованными lock fd, force TERM→KILL только собственной группе | Алгоритм сохранён; обычный stop не вызывает runner.stop и не ограничивает время ожидания |
| Ранние ошибки | DB/config имеют stderr; исключения создания/запуска Runtime могли выйти необработанным traceback | Безопасный stderr и exit 1 для runtime/config errors, без свободного текста внешних исключений |
| InstanceLock/Recovery | `locking.py`, `db_guard.py`, `monitoring.py`: lock SQLite и workspace, UUID-маркер, PID/start time, control socket, admission, read-only monitoring уже реализованы | Сохранены; Recovery меняется только в доказанной точке Git transport |
| Пути | `config.resolve_config/load_config`: explicit config → XDG; абсолютный root_path и относительные пути DB/workspace/checkout уже есть | Без изменений resolver, схемы SQLite, bootstrap и расположения данных |
| Clone/доступ | `git.checkout` и `projects.validate_remote` явно выбирали SSH; `gh repo clone` в V2 отсутствует | Прямой HTTPS `git clone` и HTTPS `ls-remote`, без зависимости от gh preference |
| Fetch/push/remote | `git.py`: fetch, publish_manual, commit_push, safe_worktree/ls-remote, conditional delete; общей проверки expected origin/pushurl не было. `Recovery.local` допускал SSH и проверял только fetch origin | Общая проверка repository/common git directory, единственных HTTPS fetch/push URL и запрет URL rewrite перед сетью; commit_push также проверяет переданный project |
| Авторизация/окружение | Git мог вызвать prompts/helpers, `projects` зависел от SSH credentials. `GhTransport` выполняет API, не доказывает Git write access | Общий noninteractive env, только HTTPS protocols, gh credential helper, без хранения токенов/login/SSH; запрет redirects и recursive submodule network |
| Локальные процедуры | `purge.py` читает старый origin для локального удаления, не выполняет удалённые Git операции; web Issues/PR links не являются transport | Без изменений |

Минимальный план, принятый по аудиту: исправить два lifecycle-дефекта и ранний
stderr; централизовать HTTPS в существующем Git adapter и project admission;
заменить SSH-проверку Recovery общей проверкой; добавить явную процедуру перехода,
автоматические проверки и документацию. Новых scheduler, resolver и DB нет.

- `src/dispatcher/__main__.py`: безопасная обработка ошибки runtime/config до логирования.
- `src/dispatcher/recovery.py`: HTTPS identity вместо разрешения SSH; отказ остаётся
  SchemaError, admission, согласование состояний и публикация не изменены.
- `src/dispatcher/error_diagnostics.py`: безопасное публичное описание transport error.
- `tests/test_https_runtime.py`: новые transport/lifecycle/data regression tests.
- `tests/local_git.py`, `tests/test_execution_cleanup.py`, `tests/test_recovery.py`:
  явный offline adapter для прежних тестов с локальными bare repositories;

- `tests/test_monitoring_projects.py`, `tests/test_error_diagnostics.py`: новые HTTPS
  аргументы и учёт локальной проверки rewrites до clone.
- `README.md`, `docs/v2.5.1-https.md`, этот отчёт: текущая авторизация, проверяемая
  процедура перехода, ручная приёмка и аудит.

Используется отдельное виртуальное окружение `/tmp/codex-v251-venv`, Python 3.14. Проверки соответствуют
существующему `.github/workflows/tests.yml`; отдельного formatter/linter config
в репозитории нет. Формат проверяется `git diff --check`, синтаксис — compileall.

Финальные результаты:

- `python -m compileall -q src tests`: PASS.

- Сборка wheel и установка `.[test]`, затем повторная установка финального wheel: PASS.

Проверен Python 3.14.4. Прогон Python 3.12 из CI matrix локально не выполнялся.

Новые проверки не используют сеть или реальные credentials: HTTPS clone при gh SSH
preference; SSH/чужой push URL/credentials/multiple URLs/rewrites fail closed;
fetch/push/ls-remote с HTTPS restrictions; reset обычного и URL-scoped credential

под admission lock; чтение завершённого future; stderr/exit code ранней ошибки;
force с живым сторонним процессом; XDG/root_path/отсутствующий SQLite без bootstrap;
исполнение документированной миграции с сохранением refs/worktrees/UUID/DB и отказом
при чужом push URL; redaction и отключение Git trace.

## Ограничения и ручная приёмка

Реальный GitHub push и Codex login не проверялись: credentials и внешние записи
не используются автоматическими тестами. Успех read-only admission не объявляется
доказательством права push. Нет systemd/Docker/установщиков и платформенной приёмки.
Автоматический переход SSH отсутствует. Документированный сценарий намеренно
ограничен стандартным служебным checkout; нестандартный пользовательский checkout
требует отдельного доказательства владения, он не переписывается скриптом.

В применимом Git config не должно быть URL rewrites, даже если оператор считает
их безопасными: это сознательный fail-closed контракт. Для GH и Codex должны быть
доступны штатные пользовательские HOME/PATH и CLI. Фиксированные таймауты отдельных
Git/API операций сохранены; общего лимита graceful drain нет.

Полный сценарий ручной приёмки и процедура SSH→HTTPS:
[v2.5.1-https.md](v2.5.1-https.md). Перед слиянием требуется отдельная ручная приёмка;
PR в рамках задания не создаётся.
