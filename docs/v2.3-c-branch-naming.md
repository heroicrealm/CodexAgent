# V2.3.C — Автоматические имена рабочих веток по issue_number

Решение пользователя: заменить глобальный GitHub `issue_id` в автоматически генерируемых названиях веток на человекочитаемый номер Issue внутри репозитория, сохраняя глобальный ID для SQLite и внутренних связей.

## Контракт

- Codex: `codex/task-{issue_number:04d}`: для #10 `codex/task-0010`, для #125 `codex/task-0125`, для #10000 `codex/task-10000`.
- Ручное исполнение: `manual/task-{issue_number:04d}`.
- Формирование происходит только в момент первоначального утверждения новой группы, когда явный `dispatcher.branch` не указан.
- Если пользователь указал `dispatcher.branch`, сохранить его без изменений.
- Исправляющие Issue (`dispatcher.correction_for`) продолжают использовать закреплённую рабочую ветку группы; новое имя не генерируют.
- Глобальный GitHub `issue_id` остаётся ключом SQLite и связей; изменения DB schema / migration не требуются.
- Не переименовывать существующие рабочие ветки и группы, уже одобренные до изменения.
- Существующую проверку занятости ветки в удалённом репозитории сохранить, не выполнять перезапись чужой ветки.
- Никаких дополнительных запросов GitHub, изменений жизненного цикла, повторных запусков Codex.

## Изменения

Найти место генерации ветки (в `StateService.approve()` используется `issue.issue_id`) и использовать `issue.issue_number` с минимальной шириной 4. Проверить другие места и тесты, предполагающие старый шаблон, без изменения внутренних идентификаторов.

## Проверки

- Номера 1, 10, 125, 9999, 10000; и Codex, и ручная задача.
- Две разные репозитории с одинаковым номером #10 не конфликтуют.
- Явная ветка не переименовывается.
- Исправляющая Issue использует ранее закреплённую ветку группы.
- Уже утверждённые группы сохраняют имя ветки после обновления.
- Конфликт имени существующей удалённой ветки не приводит к её перезаписи.
- Полный комплект тестов V2. Результаты и границы обновить в отчёте V2.3.C.

Работать в ветке `V2_3_IMPLEMENTATION`. PR не создавать. Остальные предложения V2.3.C (подробная диагностика ошибок) остаются отдельной задачей.
