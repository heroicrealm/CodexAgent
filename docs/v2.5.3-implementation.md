# V2.5.3 Ubuntu Service — аудит реализации

## Предварительный аудит

- Рабочая ветка начиналась с чистого дерева на `93aefb6`. База `9387936` подтверждена через HTTPS `git ls-remote`, поскольку SSH fetch не прошёл авторизацию. Отставание от базы — 0.
- `run` уже работает в foreground. SIGTERM переводит runtime в остановку, future дочитывается до выхода, явный `stop --force` управляет группой Codex. Runtime и потомки удерживают InstanceLock. Изменений scheduler, SQLite и Recovery не требуется.
- CLI разбирает глобальный `--config` до подкоманды. Используем существующий resolver и помещаем абсолютный результат в unit. Управление systemd выделяем до входа в DB/runtime.
- `before_run` блокирует запуск без TTY при ошибке запроса к GitHub. Сохраняем ограниченную по времени рекомендательную проверку версии.
- Standalone CLI проходит через стабильный `~/.local/bin/codex-dispatcher` и переключаемую `.venv`. Runtime и updater уже используют общую блокировку поколений. Добавляем защиту удаления программы при существующем unit и документируем ручную последовательность обновления.
- Автоматические проверки будут использовать локальные заглушки. Сигналы от реального systemd, linger, авторизация и настоящий Codex проверяются при отдельной приёмке Ubuntu Server.

## Реализация

| Файлы | Изменения |
| --- | --- |
| `src/dispatcher/service.py`, `src/dispatcher/__main__.py` | Группа `service` доступна до проверки БД. Unit с контрольной суммой, проверкой владельца, режима и namespace публикуется атомарно. Вызовы systemd и журнала передают argv напрямую. Установка выполняет enable, оператор стартует службу отдельно. |
| `src/dispatcher/releases.py` | Один запрос к latest с тайм-аутом 3 секунды. Сбой даёт предупреждение в stderr, затем CLI продолжает штатные проверки запуска. |
| `scripts/standalone_distribution.py`, `install-standalone.sh`, `uninstall-standalone.sh` | Удаление пакета отказывает при unit или enable-ссылке, включая битый симлинк. Стабильный CLI работает через переключаемое поколение. |
| `tests/test_user_service.py`, `tests/test_distribution.py`, `tests/test_https_runtime.py`, `scripts/smoke-wheel.py` | Заглушка systemd, проверки путей, отказов и сохранности данных. Реальный fake Codex без терминала, повторный SIGTERM, проверка блокировки второго runtime и завершения публикации. Полный прогон включает существующие тесты WSL2 lifecycle и Retry/Recovery. |
| `README.md`, `docs/standalone.md`, `docs/v2.5-spec.md`, `docs/v2.5.3-ubuntu-service.md` | Установка, диагностика, обслуживание и S01–S19. |

Содержимое unit меняется через `service uninstall` и повторный `service install`.
Это же применяется к смене пути конфига. `service status` показывает данные systemd
и конфигурацию unit; для состояния runtime используйте `status --json` с тем же
конфигом. Метаданные wheel пока `2.5.2.post2`, обновление версии относится
к подготовке согласованной публикации по [регламенту](releasing.md).

## Приёмка

Реализация готова к ручной приёмке. В WSL2 пользовательский D-Bus недоступен.
Ожидаются результаты всех S01–S19 на Ubuntu Server. В частности, S08/S09/S18
должны подтвердить поведение `KillMode=mixed` с живыми потомками, а S19 —
linger после выхода и reboot, настоящий Codex без TTY, авторизацию и GitHub push/PR.
S13 требует двух совместимых Standalone-сборок. Команды и критерии приведены
в [руководстве оператора](v2.5.3-ubuntu-service.md#ручная-приёмка-s01s19).
